## イシューを1つ消化したら、サーバも手元もアップデートする
**新しい版を触らないと評価できない。** テストが緑なだけでは利用者は何も確かめられないので、配って初めて評価できる。

**ただし、いまリモート経路は無い。** スマホから触るものは**リモート経路（サーバ → セッションホスト）でしか再現しない**が、**サーバは 2026-08-15 に消えた**（下記の段2）。**スマホでの確認を要する受け入れは、サーバを立て直すまで踏めない。**「配ったから確かめられる」と書いてある計画に当たったら、そこで止まることを先に見込むこと。

### 既定は「押す直前」まで。落とすところで止まる
**エージェントが勝手に進めてよいのは、落ちないところまで。** 走っている claude が死ぬ操作は、**頼まれたときだけ**行う。

| 段 | 何を | 既定で誰がやるか | 落ちるか |
|---|---|---|---|
| 1 | **配る**——版を上げて**タグだけ**を打つ（リリース本体は `dist` が作る。**人が手で `gh release create` を叩かない**——`release.yml` の中で `dist` が呼ぶのは正常） | **エージェント** | 落ちない |
| 2 | ~~**サーバ**——`~/compose.yml` の `image:` を書き換え、`docker compose pull` → `up -d`~~ | **【いまは踏めない】** | — |
| 3 | **手元に新しい実行ファイルを用意する**——**実機ツリー**（`~/AgentDashboard`）で `git pull` → `make build`。**開発ツリー（`~/Dev/AgentDashboard`）で建てても実機は変わらない** | **エージェント** | 落ちない（作るだけ） |
| 4 | **効かせる**——起こし直す／「いま入れ替える」 | **人**（頼まれたときだけエージェント） | **抱えている claude が道連れになる。**ダッシュボード自身は同じ PID のまま新しい版へ入れ替わって戻ってくる（`手元の新しい版をGUIだけで効かせる`） |

**段3の「手元」は、いま作業しているツリーのことではない。** この機械にはクローンが2つあり、**`~/Dev/AgentDashboard` は書く場所、`~/AgentDashboard` は走る場所**である。常駐しているダッシュボードは後者の実行ファイルから起きているので、**開発ツリーで `make build` しても画面には何も出ない**。**間違えても何も落ちないので、報告するまで気づけない**——建った実行ファイルは実在し `--version` も新版を答える。確かめ方は、画面の「ダッシュボードの版」に出ている**絶対パス**と、自分が建てた場所を突き合わせること（詳しくは `ガイドライン/長く生かしたいプロセスを起こすとき`）。

**段2は無い。いま踏めるのは1・3・4である。** 置いてあった AWS は**無料プランの期限切れでアカウントごと閉鎖**され（2026-08-15）、`dash.underschaft.com` は HTTP 530、SSH も AWS の認証も通らない。**「認証を入れ直せば入れる」と読まないこと**——失効ではなく閉鎖なので、入口そのものが無い。**行を消さずに取り消し線で残してあるのは、立て直したときに同じ手順が再び効くからである。**

戻す道は「有料プランへ移す」か「別の場所へ立て直す」の2つで、**どちらを選ぶかは人が決める。** 現況は `.claude/docs/knowledge/いま動いているもの.html` が正。

**つまり既定の完成形は「新版をいつでも使える状態にして、押す直前で止める」である。**

**ただし「押す直前で止める」は、コミットを後回しにする理由にはならない。** 段1（配る）を
後回しにする判断はよいが、**未コミットのまま止まると、セッションが閉じた瞬間に成果が
宙に浮く**——ここは同じツリーを複数のセッションが触るので、**他人の `git add -A` に
巻き込まれるか、`reset` で消える**（実際に複数回起きている）。**保存（コミット）と
配布（タグ）は別の動作である。** 詳しくは `ガイドライン/unreleased-work.md`。

段4 まで頼まれた場合だけ、エージェントが同じイベントを CLI で発火する（下記）。

**権限確認は要らない**（利用者の指定）。ただし**危ないものをリリースに含めないことは必須**——本リポジトリは公開なので、フィクスチャ・ログ・スクリーンショット・録画に認証情報や個人情報が混ざっていないかを、**配る前に**確かめる（`scripts/sanitize-fixtures.py` の残存検査。ガイドライン「フィクスチャを採取するとき」）。

**段4 で止めたときは、何をすれば効くのかを渡す。** 「用意はできています」だけでは、次に何を押せばよいのか分からない——**そのまま貼れるコマンドか、押すボタンの名前**を書いて終わること。

### 落とす前に、抱えている claude を数える
セッションホストを起こし直すと**子の claude が道連れになる**。`ps -eo pid,ppid,args --forest` で子を数え、**0本でなければ止まる**こと。

**自分自身がその子であることがある。** ダッシュボードから起こされたセッションで作業していると、セッションホストを落とす＝自分を殺すことになる（実際に踏んだ）。そのときは**落とさずに利用者へ渡す**——「いつ落としてよいか」は人にしか決められない。

実機（ローカルモード）も同じで、**生きたカードが0枚**であることを数えてから落とす。数えた結果が分岐に入っていない書き方（`数える; kill`）は数えていないのと同じ。

### 「更新する」ボタンを押すのは人
**この機能は、いつ落とすかを人が決めるために在る**（CICD イシューの要件そのもの——「勝手に更新された結果、いま起動しているセッションや表示が停止したり壊れたりしたら嫌なので、ユーザーのタイミングで」）。版を切り替えるとプロセスが落ち、**走っているセッションが道連れになる**。だから**勝手に取ってこないし、勝手に切り替えない。**

流れは3段で、**どこまで進んでも、押すまでは何も起きない。**

```
新しい版が出た → 「新しい版があります」と出る（見に行くのは1日1回まで）
  → 押したときだけ取ってくる（<state_dir>/versions/ へ）
  → 選ぶ＝予約。**次に起こしたときに効く**（この時点では何も落ちない）
  → すぐ効かせたいときだけ「いま入れ替える」（**ここでだけ落ちる**。何枚が抜け殻になるか数が出る）
```

**押すのは人**（頼まれたときだけエージェントが押す）。

**押す道があるかは、そのものが何かで決まる。** 「ソースビルドかどうか」ではない。

| どれ | 版のカード | 上げ方 |
|---|---|---|
| **ダッシュボード**（実機・配布バイナリとも） | **出る**（`supported`） | ①画面から上の3段　②**ソースビルドも画面から押せる**——`make build` すると「ディスクに新しい版があります」が出て、**予約を1つも作らずに**「いま入れ替える」が押せる（`手元の新しい版をGUIだけで効かせる`。それ以前は画面に何も出ず、CLI か手作業しか道が無かった） |
| **セッションホスト** | **無い**（エージェントなので画面を持たない） | 実行ファイルを置き換えて起こし直すしかない。**ここだけは押す道が無く、抱えている claude が必ず道連れになる** |
| **docker compose** | 出ない（箱の中で入れ替えても次の起動で消える） | `image:` を書き換えて `pull` → `up -d`。**ただし、いま動いている箱は1つも無い**（AWS は閉鎖済み。上の段2） |

**予約が残っていると、起こし直したときにそちらへ乗り換わる。** ソースビルドを新しくしたのに版が変わらないときは `<state_dir>/version-current` を見ること（無ければ実行ファイル自身の位置から起動する）。

### エージェントが押すときは、CLI の口を使う。手で組み立てない
画面のボタンは**すべて CLI から叩ける**（`cli_surface.toml` に 1:1 で載っている）。頼まれてエージェントが上げるときは、こちらを使う。

| 画面のボタン | CLI |
|---|---|
| 新しい版を取ってくる | `agentdashboard version install <版>` |
| 選ぶ（予約） | `agentdashboard version select <版>` |
| **いま入れ替える** | **`agentdashboard version restart`**（強行は `--force`） |

**`version restart` には「生きたカードが1枚でもあれば数を言って止まる」が入っている。** `curl /api/sessions` で数え、`ss` で PID を引き、`kill` して起こし直す——という一式を手で書くと、**既にある保護を作り直すことになる**。結果が同じでも、作り直した側には台帳も検査も付いてこない。

### 実機（開発機）だけは、取ってくる・予約を使わない
**`version select` で予約を入れると、以後の `make build` が効かなくなる**（起動のたび保管庫の版へ乗り換わるため）。実機はソースを追いかけたい機械なので、予約は入れない。

**予約を使わないことと、画面から押せることは両立する。** ボタンの出る条件は「予約があるか」ではなく**「走っている版 ≠ 次に起きる版」**なので、`make build` した実機は**予約ゼロのまま**押せる（`手元の新しい版をGUIだけで効かせる`）。

したがって実機の形はこうなる。**1行目までが既定、2行目は頼まれたときだけ。**

```
make build                          # ← ここまでが既定（落ちない）
─────────────────────────────────── 頼まれたときだけ、この線を越える
agentdashboard version restart      # 生きたカードがあればここで止まる
```

**起こし直す行は要らない。** `version restart`（と画面の「いま入れ替える」）は、落ちるのではなく**その場で自分を新しい実行ファイルへ入れ替える**（`exec`）ので、**同じ PID のまま戻ってくる**。常駐の仕組みに載せていなくてよいのはこのためで、案A（systemd の user unit）は不要になった。

**入れ替えられなかったときも落ちない。** 行き先が起動できなければ古い版のまま生き残り、理由が画面に残る——この道を作った理由が「落ちても誰も起こさない機械がある」ことなので、失敗してなお落ちると押す前より悪い。

**ただし抱えている claude は道連れになる。** 待ち受けも PTY も `CLOEXEC` が付いているので `exec` で全部閉じる。落ちないのは**ダッシュボード自身だけ**である。

### 効かせたあとは、タブの読み込み直しを促す
画面（HTML と JavaScript）は**実行ファイルの中に焼き込まれている**ので、**開きっぱなしのタブは古い画面のまま**新しいサーバと喋り続ける。

**版の数字は当てにならない。** ヘッダに出る版は毎回サーバに聞いた答え（`/api/me`）なので、**古いタブでも新しい版が表示される**。数字は合っているのに振る舞いだけ古い、という形になる。

気づけるように、版が変わったらバナーが出る（`stores/auth.ts`）。**勝手には読み込み直さない**——書きかけの指示が消えるため。**読み込み直しはタブごと**なので、PC とスマホの両方で開いているなら両方で押す必要がある。

## 計画とテスト計画の最終フェーズに、アップデートを含める
`計画.md` と `テスト計画.md` を作るときは、**最終フェーズに「配る・手元」を必ず入れる**。受け入れは新しい版を触らないと成立しないので、ここが無いとイシューを閉じられない。

**【要人間】の項目は、この2つが揃ってからしか着手できない**ことも書き添える。順序を書いておかないと、配る前にスマホで確かめようとして時間を溶かす。

**「サーバ」の段は書かない。** かつては3つだったが、**サーバは無くなった**（上の段2）。書くと、踏めない項目が未消化のまま毎回積み上がる。**スマホからの確認を要する項目は、立てられないことを理由に【保留】として分けておくこと**——【要人間】に混ぜると、人が居ても踏めないものと、人さえ居れば踏めるものが見分けられなくなる。

## プロジェクト概要
**AgentDashboard** は、複数プロジェクト・複数セッションの Claude Code を一望する個人用の司令塔ダッシュボード。ローカルで動く Web アプリとして提供し、ブラウザから閲覧・操作する。

中心にあるのは「**実行は本物のCLI、表示は構造化UI**」という考え方。サーバは擬似ターミナル（PTY）上で本物の claude CLI を起動するので `/rewind` を含む全スラッシュコマンドが使える。一方で画面は ANSI 出力の解析ではなく、Claude Code が書き出す構造化トランスクリプト（JSONL）とフックイベントから組み立てる。

技術構成は Rust（axum + portable-pty）のバックエンドと React 19 + TypeScript のフロントエンド。JSONL のフォーマット変更に自動対応する自己修復機構を持ち、その変更範囲を物理的に限定するためパーサだけを別プロセスへ切り出している。

## 用語
**この道具はコーディングエージェント（claude）を複数動かして管理するもの**なので、「エージェント」という語は claude の側に取ってある。それを抱えている常駐プログラムを同じ語で呼ぶと、読むたびにどちらの話か考えることになる。

### 言い換えの表
| 区分 | 旧名 | 新名 |
|---|---|---|
| 呼称 | PC 側エージェント／エージェント | **セッションホスト**（文脈が明らかなら「ホスト」） |
| 呼称 | ハンバーガー／ハンバーガーボタン／フォルダのオーバーレイ | **サイドバー**（2026-08-27・利用者の指定） |
| crate | `session-host-core` | `session-host-core` |
| crate | `agentdashboard-agent`（`crates/agent`） | `session-host`（`crates/session-host`） |
| 型 | `SessionHost` ／ `SessionHostHub` ／ `SessionHostConn` ／ `SessionHostCommand` | `SessionHost` ／ `SessionHostHub` ／ `SessionHostConn` ／ `SessionHostCommand` |
| 型 | `RemoteSessionHost` ／ `LocalSessionHost` | `RemoteSessionHost` ／ `LocalSessionHost` |
| 型 | `SessionHostConfig` ／ `SessionHostLink` ／ `SessionHostView` | `SessionHostConfig` ／ `SessionHostLink` ／ `SessionHostView` |

### 利用者の語法（画面の呼び方）
**利用者が「セッション画面」と言うとき、指しているのは2つある。**

| 言い方 | 指しているもの |
|---|---|
| **セッション画面** | **セッション専用画面（`/s/:cardId`）と、PJT 専用画面に横並びで出る各セッションの区画の両方** |
| セッション専用画面 | 単独で開いたほう（`/s/:cardId`）だけ |
| PJT 専用画面 | `/p/:host/:project`。中にセッションの区画が横並びで入る |
| 小窓（カード） | 一覧に並ぶタイル |
| **サイドバー** | PJT 専用画面／セッション専用画面の**左から出てくるフォルダの区画**と、それを開け閉めするボタン |

**サイドバーは「ハンバーガー」と呼ばない**（2026-08-27）。印が☰でなくなるので、名前だけが残ると次に読む人が画面上に無いものを探すことになる。

**ただし「オーバーレイ」は一括で消さない。** サイドバーは**狭い窓では実際に被さる**（広い窓では右のものを押しのける）ので、狭い窓を指す用法の「オーバーレイ」は正しいまま残る。上の「守ること」と同じ理由で、1件ずつ意味を見る。

**片方だけに実装して「入れた」と言わないこと。** 横並びは `SessionView` を `compact` で並べたものなので、**`SessionView` へ置けば両方に出る**——逆に、単独画面の側だけへ足すと横並びに出ない。

**`compact` で出さない判断には理由が要る。** 十字ボタンは横並びで出さないと決めているが、あれは**宛先が1つに定まらない**ため（方向キーをどの端末へ撃つのか曖昧になる）。**カードごとに宛先が一意な操作には、この理由は当てはまらない。**

**逆に、片側だけに出すのが正しいものもある。** **行き先が「いま居る画面」になるとき**がそれで、押しても何も起きないものを置くと**壊れているのと見分けが付かない**。行き来の導線がこの形になっている（`v0.1.53`）。

| どちらに出るか | もの | なぜ片側なのか |
|---|---|---|
| ~~**単独画面だけ**~~ | ~~パスを押すと PJT 専用画面へ移る~~ | **【2026-09-02 に置き換わった】** |
| ~~**横並びだけ**~~ | ~~「開く」を押すとセッション専用画面へ移る~~ | **同上** |

**行き来は1つの切替ボタン（拡大／縮小）になった**（`DESIGN.md` §39.5・帯設計§17-3）。**両方の画面の同じ場所**（操作列の中・ターミナルトグルのすぐ右）に出て、**向きだけが変わる**——PJT 専用画面では拡大、セッション専用画面では縮小。

**「行き先がいま居る画面になる」という片側だけの理由は、切替ボタンには当たらない。** あれは**常に別の画面へ行く**ので、片側に出さない理由が消えた。**上の2行は、何が置き換わったかを読めるように残してある。**

**片側だけに出すものが無くなったわけではない。** いまその形なのは**画面の帯**そのもので、**横並びでは描かない**——サイドバー・PJT 名・✕ はどれも横並びでは出さないので、**中身が1つも残らない**（`DESIGN.md` §39.4「空の段を作らない」）。

**どこに置くかは `DESIGN.md` §39 が正。** 上の表は「出す／出さない」の話だが、**出すと決めたものをどこへ置くか**は別に決めてある——**操作は、それが効く相手と同じ入れ子に置く**（セッションに効くものはセッションの区画の真上、画面に効くものは画面の帯）。**セッション専用画面はセッションが1本しか無いので、この2つが見た目には重なる**が、重ねて実装すると PJT 専用画面と食い違う。**片方を直したら、必ずもう片方と並べて見ること。**

### 据え置くもの（変えてはいけない）
| 据え置くもの | なぜ |
|---|---|
| バイナリ `agentdashboard-agent` | **既に入れた人の環境が壊れる**（入れる側・消す側・手順書がこの名前を指している） |
| 設定ファイル `agent.toml` | 同上 |
| URL `/agent/ws`・JSON の `agent_id` | **版交渉の相手（古い PC）が繋がらなくなる** |
| DB の `agents` 表・`agent_id` 列 | 移行が要る |
| `crates/protocol` の型（`AgentMessage` ／ `ServerToAgent` ／ `AgentId`） | 共有境界で変更のハードルが高く、**据え置く線の名前と対**になっている。型だけ変えると型と線の名前がずれる |
| `AgentMeta`（`transcript-parser`） | **これは本当にコーディングエージェント**（claude のサブエージェント）。残すのが正しい |

### 守ること
- **旧名を見つけ次第、その場で直す。** 別の作業の途中でも、目に入ったら直す。一括置換の日を待たない
- **一括置換で直さない。** 「エージェント」には**コーディングエージェントを指す正しい用法**が混ざっている（実装方針の文、`transcript-parser` の親子関係の説明、`protocol.ts` の申告の説明など）。1件ずつ意味を見る
- **新しく紛らわしい語が出たら、この表へ足してから言い換える。** 表に無い言い換えを勝手に始めない——人によって別の名前を使い始めると、旧名より状況が悪くなる

## ドキュメント参照ガイドライン
**このリポジトリへ初めて入るときは、まず `.claude/docs/knowledge/このリポジトリの読み方.md` を読む。** どこから読めば最短で作業に入れるか、仕様の正がどこに散っているか、読み違えやすいところが書いてある。

初期実装の仕様の正は `MyDocs/ローカルイシュー/クローズ/初期実装/` にある。読む順序は次のとおり。

| ドキュメント | 何が書いてあるか |
|---|---|
| `要件.md` | 何を作るか・なぜ作るか・スコープ |
| `方針.md` | 技術選定とその理由、実機検証の記録 |
| `設計.md` | §1〜§14 の詳細設計。実装時に最も参照する |
| `テスト計画.md` | フェーズ1〜8のテスト項目 |
| `計画.md` | フェーズ0〜6の実装タスクと ⛳チェックポイント |
| `実行レポート.md` | 各フェーズで実際にやったこと・起きた問題・引き継ぎ |

`計画.md` と `テスト計画.md` は設計を `§N` の形で参照している。**設計.md の既存節番号は振り直さない**（詳細は `.claude/docs/guideline.md`）。

**ただし、いまの仕様はこの一式だけでは説明できない。** ここが扱うのはフェーズ0〜6＝ローカルモードまでで、DB の語が1度も出てこない。後から足した機能（セルフホスト化・版の切替・CLI の口・ログ）は、**それぞれのクローズ済みイシューが正**である。対応は上記の読み方にまとめてある。

実装の進め方は「人間の手作業を介さず、エージェントが実装からテストまで自律的に完走する」ことを基本方針とする。人間の関与が原理的に避けられないタスクには `計画.md` 上で **【要人間】** が付いている。

環境や依存の扱いは `.claude/docs/knowledge/` を参照。

**常駐しているものに触る前に `.claude/docs/knowledge/いま動いているもの.html` を読む。** どのポートで何の版が動いていて、どの URL がどれを指しているかが書いてある。**URL とその先の対応を取り違えると、原因追跡が丸ごと空振りする**（実際に起きた）。起こす・落とす・張り替える・外に立てるをしたら、その場でここを直す（`.claude/docs/guideline.md`「長く生かしたいプロセスを起こすとき」）。

## 品質ガイドライン
- **cargo は必ず `scripts/cargo` 経由で呼ぶ**。ホストに Rust ツールチェーンは入っていない
- タスク完了の定義は「テストが通ること」。`make ci`（lint → test → build）が通って初めて完了とみなす
- 各フェーズの終わりには ⛳チェックポイントがあり、対応するテスト計画のフェーズを消化してから次へ進む
- 自己修復機構の制約上、`crates/protocol` は共有境界であり変更のハードルが高い。未知の構造は `Node::Unknown` へ写像して吸収する
- **原因を追うときは、コードを読む前に `agentdashboard logs` を読む。** 残す側の約束は `.claude/docs/guideline.md`「ログを残すとき」に集めてある（利用者向けの読み方は `README.md`）
- コミットは作業別に分けて段階的に行う。プッシュはしない
