# 改善記録

このスキルの実行中に起きた、**手順どおりにやったのに期待どおりにならなかった事象**をここに記録する。

記録したら、対処が手順に落とせるものは `SKILL.md`・`mainflow.md`・`knowledge/paths.md` のどれかへ反映すること。**ここに書いただけでは次回の失敗を防げない。**

---
<br/>
<br/>

## 記録する対象

- `ad logs`／`ad state-dir`／`running-state` の引数や出力形が変わり、`bin/collect`・`bin/narrow`・`bin/report-draft` が想定どおり動かなかった（**道具側の変化を追い切れていない可能性が高い**）
- `knowledge/paths.md` の経路表（`proc`／`target`／`kind` の対応）が実物のログと食い違っていた（新しい `target` が出た、既存の分類が経路を取り違える、など）
- `--sanitize` の伏せ字範囲が変わり、`bin/report-draft` が生の値を「該当行」欄へ漏らした、または逆に必要な情報まで消してしまった
- 段0〜段4の「止まる条件」が実際の調査では発火しなかった、または発火すべきでない場面で発火した
- 段2の並行ワーカー分担（`subagent_type: "general-purpose"`／`model: "sonnet"`）まわりの起動・統合の挙動が、想定と違った

---
<br/>
<br/>

## 記録しないもの

- 一度きりの偶発的なミス
- 外部要因（実機が一時的に落ちていた、ネットワーク断など）
- **手順を実行しなかったことによる失敗**（それは手順の問題ではない。ただし「守られない手順」が繰り返されるなら、それは書き方の問題なので記録する）

---
<br/>
<br/>

## ファイル名

`YYYY-MM-DD_何が起きたか.md`（日本語可）。**症状ではなく、そこから得た教訓が分かる名前にする。**

---
<br/>
<br/>

## 中身

1. **何が起きたか**（観測した事実。推測と分けて書く）
2. **なぜ起きたか**（分かった範囲で。分からなければ「未特定」と書く）
3. **どこを直したか**（`SKILL.md` / `mainflow.md` / `knowledge/paths.md` のどれをどう変えたか。直していないなら「未対応」と理由）
