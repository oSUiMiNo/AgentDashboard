# 手順書と ship が同じ配布を二重に指示していた

---
<br/>
<br/>

## 何が起きたか
`mainflow.md` §6-4 が「コミットして main とタグを push し、押し終えたら `bin/ship` を実行する」と書いていた。
ワーカが手順どおり手で配ったあと `ship` を呼ぶと、`ship` が同じコミット・push・タグを繰り返そうとして「タグ v0.1.148 は既に存在します」（終了コード2）で止まった。
配布そのものは手で済んでいたので実害は無かったが、門の結果が赤として報告された。

---
<br/>
<br/>

## なぜ
`ship` はコミット → main の push → タグ → タグの push を一続きで行う道具だが、手順書は `ship` を「押したあとの確認」のように書いていた。
手順書と道具のどちらも、相手が同じことをすると知らなかった。

---
<br/>
<br/>

## どこを直したか
`mainflow.md` §6-4 を「門3が緑なら `ship` だけを呼ぶ。`ship` の前に手でコミットや push をしない」に直し、古い書き方は取り消し線と覆った日付を付けて残した。
