## ここに書くこと
`version_release` 自身の動作・ルーティング・プロトコル・ツール選択に問題があったとき、その内容と直した内容を記録する場所。判断の問いは「この改善は、このスキルが全く別のプロジェクトで使われても同様に必要か」——YES ならここ、NO なら PJT ガイドライン（このスキルの動作自体に問題は無く、PJT 固有のワークフローが原因のとき）。

**何も壊れなかったが、無駄な往復が発生したときも書く。** 例：`claim` が終了3を返して待たされた、門の赤を見落として次の段へ進みかけた、`periodic` の入口判定を誤って二重に走らせかけた、など。壊れていないことと、改善の種が無いことは別。
