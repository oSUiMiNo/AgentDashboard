# Bash 由来の推測が文の断片を「触ったファイル」として拾い、セッション ID が環境に無かった（2026-11-22）

---
<br/>
<br/>

## 何が起きたか
- `touched-files --porcelain` の「触った が dirty でない」の群に、パスではない文の断片が20行ほど並んだ。例：`14.4`・`4.69`・`Math.round(c.getBoundingClientRect().width))`・`` `（v2.1.327）**：JSON `` など。このセッションでは、Python のヒアドキュメントで JSON の台帳を書き換え、Playwright の評価式を含む指示文を Bash で書いていた
- 「触った かつ dirty」の群（自分が直した2ファイル）は正しかった。コミットの判断は、この群と `git diff --cached` の目視で足りた
- Bash の環境に `CLAUDE_SESSION_ID` が無く（`unset`）、手順の `--session "$CLAUDE_SESSION_ID"` のままでは空の値が渡る。セッション ID を手で渡して動かした

---
<br/>
<br/>

## なぜ起きたか
- Bash 由来の推測（ヒアドキュメント・`sed -i`・`>` などを正規表現で拾う）が、ヒアドキュメントの中身の文字列や、Python の文字列リテラルの中の `>`・`.` を、書き込み先のパスと読んでいる見込み（未確認）
- `CLAUDE_SESSION_ID` が Bash の環境へ渡らない場面がある理由は未特定

<br/>

## どこを直したか
- 未対応。`mainflow.md` の Phase 1 には「Bash 由来は推測にすぎない」と既に書いてあり、今回も Phase 4 の目視で裏が取れたので、手順の結論は変わらない
- 直すなら：`touched-files` が、Bash 由来の候補のうち実在しないパス（`git ls-files` にも作業ツリーにも無いもの）を落とす。`--session` が空なら、`~/.claude/projects/<slug>/` の最新の `.jsonl` を使うか、空であることをエラーにする
