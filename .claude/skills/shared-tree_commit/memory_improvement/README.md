# 改善記録

このスキルの実行中に起きた、**手順どおりにやったのに期待どおりにならなかった事象**をここに記録する。

記録したら、対処が手順に落とせるものはその場で `mainflow.md` へ反映すること。**ここに書いただけでは次回の失敗を防げない。**

## 記録する対象

- `bin/touched-files` の「Bash由来（不確か）」が、実際には触っていないパスを拾った・触ったパスを拾い損ねた
- 他人のハンクを自分のコミットへ含めてしまった（`git add <ファイル>` した後の判定漏れ）
- `claim` の終了コード判定が想定と違った（0／3 以外が返る、`ls` の出力形式が変わった等）
- セッション記録（`.jsonl`）が見つからず §10-4 の手動判定へ落ちた——その頻度や原因
- 作業単位の切り方の判断が、後から見て粗すぎた・細かすぎた
- 終了時の振り返り（Phase 6）で見つかった「無駄だった読み込み・往復」

## 記録しないもの

- 一度きりの偶発的なミス
- 外部要因（ネットワーク断、ディスク逼迫など）
- **手順を実行しなかったことによる失敗**（それは手順の問題ではない。ただし「守られない手順」が繰り返されるなら、それは書き方の問題なので記録する）

## ファイル名

`YYYY-MM-DD_何が起きたか.md`（日本語可）。**症状ではなく、そこから得た教訓が分かる名前にする。**

## 中身

1. **何が起きたか**（観測した事実。推測と分けて書く）
2. **なぜ起きたか**（分かった範囲で。分からなければ「未特定」と書く）
3. **どこを直したか**（`mainflow.md` をどう変えたか。直していないなら「未対応」と理由）
