# 「戻すと落ちる」検査で赤くならなかったとき、疑う順序

`bin/revert-check` がコミットを戻してもテストが赤くならなかったとき、原因を当てずっぽうで探さない。次の4つを、この順番で疑う。**このドキュメントは診断の材料を並べるだけで、直しはしない**——直す先は該当する持ち主（テストの書き手・実装の持ち主）に委ねる。

---
<br/>
<br/>

## 1. 測る相手が違う（判定は渡されたものしか見ていない）

**見分け方**：戻したはずのコードが、実は実行対象に反映されていない。`make build-web build-debug` の対象が、意図した worktree ではなく別の場所（実機ツリー・別の worktree・キャッシュされたビルド成果物）を指していないかを確認する。特に Web 側は、`web/dist` などのビルド成果物が古いまま残っていると、ソースを戻してもテストは古い成果物を見続ける。

**直し先**：`revert-check` の実行時に使ったパスと、テストが実際に読みにいったパスを突き合わせる。ビルドキャッシュを疑うなら、当該 worktree でのクリーンビルドを確かめる。

---
<br/>
<br/>

## 2. 材料が弱い（判定は渡されたものしか見ていない、の別形）

**見分け方**：戻したコミットが、実は守りたい振る舞いの本体ではなく、周辺の些末な変更（コメント・フォーマット・無関係な行）しか含んでいなかった。台帳の `breaks_when` に書かれている壊し方と、実際に `--commits` へ渡したコミットの diff を見比べる。

**直し先**：台帳の `breaks_when` を書いた本人に、対象コミットが正しいかを確認する。正しい壊し方に対応するコミット（または `git revert` ではなく直接コードを1行変える手法）に差し替える。

---
<br/>
<br/>

## 3. 観点が足りない（jsdom は CSS を1バイトも当てない、の一般形）

**見分け方**：テストの実行環境が、壊れた振る舞いを観測できる立場にない。典型例は、見た目・レイアウトに関わる変更を vitest（jsdom）で確かめようとしている場合——jsdom は CSS を適用しないため、CSS 由来の壊れ方はどれだけ戻しても赤くならない。同様に、E2E でしか踏めない経路（実ブラウザでのみ発火するイベント、実ネットワークでのみ現れる遅延）をユニットテストで確かめようとしていないかも見る。

**直し先**：テストの種別（`gate` の値：`unit`／`e2e`／`manual`）が、壊したい振る舞いの性質と合っているかを確認する。合っていなければ、`gate` を実ブラウザで確かめる E2E か、機械検査の効かない `manual` へ引き直す。

---
<br/>
<br/>

## 4. 守っているのは別の指定（部分一致の検査は空になる、の一般形）

**見分け方**：テスト名や検査条件が、意図した対象より緩く（または全く別のものに）一致している。例えば `gap-1` を狙った検査が `p-1` にも一致してしまうような、文字列の部分一致による見かけ上の的中。テストの assert が実際に何を測っているかをテスト本文で直接確認する。

**直し先**：assert の対象を、狙った振る舞いだけに一致するよう絞り直す（完全一致・要素の構造ベースの比較など）。絞り直したら、わざと壊して赤くなることを確認してから元に戻す。

## check-docs の限界

`bin/check-docs` と、同じ形で判定を返す `bin/ledger-lookup`／`bin/revert-check` にも、機械では埋めきれない緩さがある。判定が「OK」「合格」と出ても、下記の観点までは検査していないことに注意する。

### §9-2-1：「配る・手元」への言及は、キーワードの緩い一致でしか見ていない

`check-docs` の `check_release_mention()` は、実際の文書が2通りの形（最終H2見出し自身が言及する形／実行レポート.md には無くクローズレポート.md 側にある形。例：`クローズ/イシューグループ_2026-0914-1041` は後者）のどちらでも通るように、厳密な構造チェックをせず、実行レポート.md の最終H2セクション本文（無ければクローズレポート.md の見出し）に「配る｜手元｜リリース｜release｜タグ｜tag｜version_release｜版」のいずれかが出現するかで判定している。**文脈は見ていない**——無関係な文脈でこれらの語が出現しても「言及あり」と誤判定しうる。

### revert-check の非 dry-run 実行は、委譲の強制ができない

`revert-check` は `--dry-run` を外すと `make build-web build-debug` を含む重い操作を実行する。`mainflow.md §9-3` の規約上、呼び出し側は Agent ツールで `subagent_type: "general-purpose", model: "sonnet"` を明示してワーカーへ委譲した上でこのスクリプトを実行することになっている。**しかしスクリプト自身はこの委譲を強制できない**——直接呼び出しても止まらずに実行してしまうので、規律は呼び出し側に委ねられている。
