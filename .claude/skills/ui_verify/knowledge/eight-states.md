# 8つの状態を作る段取り（状態表示を触ったときだけ読む）

毎回の検収では読まない（設計.md §11-4）。状態表示（アイコン・バッジ・色）に関わる画面/ファイルを触ったときだけ、段4（撮る）の直前に読む。

---
<br/>
<br/>

## なぜ順序が要るか

状態は一方向のラッチで進むものがあり、不明（unknown）のような状態は一度別の状態へ進むと後戻りしない。狙った状態を後から作ろうとしても、既に進んでしまった状態からは戻せない。だから8つの姿を「後戻りしない順」に並べ、その順で作る。

---
<br/>
<br/>

## 8つの姿を作る段取り

1. **不明用のカードを置く**——素材（プロジェクト専用スキル案.md 案4）の起点。ここから他の状態へ進める。
2. **停滞用のカードを作業中にする**——停滞は「作業中のまま閾値を跨いだ」姿なので、先に作業中を作ってから停滞させる。
3. **フックを撃つ**——フック経由でしか作れない状態（許可待ち等）をここで作る。
4. **異常終了を作る**——プロセスを異常終了させて、その姿を固定する。
5. **閾値を跨がせる**——停滞判定の閾値を実際に跨がせて、停滞状態を確定させる。
6. **作業中・起動中は最後に作る**——この2つは時間が経つと別の状態へ進んでしまうため、他の6つを作り終えてから、撮る直前に作る。

## 撮るときに踏み外しやすい点

### 作業中と起動中は撮る直前に作り直す

作業中・起動中は閾値を跨ぐと停滞・不明へ落ちる。先に作っておいて後で撮ると、撮る頃には別の状態へ進んでしまっていることがある。撮影の直前に作り直すこと。

### 設定を REST で書いたらページを読み込み直す

設定を REST 経由で書き換えても、開いたままのページは古い設定を読んだままのことがある（`data-quiet` 印の誤読の原因になる）。REST で書いたら、対象のページを読み込み直してから撮る。

### 比べる絵はアニメーションを山で止めて撮る

状態を比べる絵は、アニメーションの途中の任意の瞬間ではなく、山（ピーク）で止めて撮る。途中で撮ると、同じ状態でも撮るたびに絵が変わり、比較にならない。

### 立てる作法

自己修復機構を切り（`selfheal_enabled = false`）、専用の置き場所（サンドボックス専用の `state_dir`）を使い、本物の claude ではなく擬似claude（`fake-claude`）を使い、停滞の閾値を縮め（`stalled_threshold_secs` を小さくする）、版の乗り換えを塞ぐ（`AGENTDASHBOARD_VERSION_HANDED_OVER` / `AGENTDASHBOARD_VERSION_SUPPORTED` の固定）。これらは mainflow.md 段3 が呼ぶ `sandbox-dashboard up` が既に行っている（`bin/capture-plan` 自身は URL・幅・保存名の計画を出すだけで、サンドボックスは立てない）。

### 撮ったら参考へ置く

撮った絵は会話に出して終わりにせず、`参考/YYYY-MM-DD_<フェーズ>_<画面>_<幅>.png` へ置く。物差しは「決まっている・静かに壊れる・重ならない・次の判断に使える」の4つ（プロジェクト専用スキル案.md 案4）。
