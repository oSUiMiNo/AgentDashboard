# 区画の幅を撮る計画が無い

---
<br/>
<br/>

## 何が起きたか
Markdown ブロック編集で、利用者が**ファイル表示の区画だけ**を狭めたときに、ブロックハンドルが区画の外へはみ出す・反転して横スクロールを生む不具合が出た。
このスキルの撮影計画（`bin/capture-plan`）は「PC 幅」と「約 400px の画面幅」の2通りしか持たないため、**画面は広いまま区画だけが狭い状態**を1枚も撮らない。
既存の狭い幅の E2E も画面幅 400px で測っていたので、同じ理由で見逃していた。

---
<br/>
<br/>

## なぜ
画面全体の幅（ビューポート）と、部品が置かれた区画の幅は別物である。
区画の中の部品は、区画の幅で崩れる（例：区画幅で切り替えるべき配置を `@media` の画面幅で書いていた）。
画面幅だけを変えても、区画の幅は「画面幅に比例して縮む」形でしか変わらず、区画だけ狭い組み合わせが現れない。

---
<br/>
<br/>

## どこを直したか
`bin/capture-plan` は直していない（4枚の計画の枠を変えると、既存の検収記録と並べて比べられなくなるため、枠の変更は設計.md へ戻して決める必要がある）。
代わりに、**区画の中の部品を触ったときは、画面幅とは別に区画幅を変えて撮る**ことを、この記録で残す。
実際に効いたやり方の例：部品だけを載せた試作ページに区画幅を URL で渡せるようにし（例：`?w=360`）、画面は広いまま区画を 320〜800px で変えて、ハンドル等を出した状態で測った。
