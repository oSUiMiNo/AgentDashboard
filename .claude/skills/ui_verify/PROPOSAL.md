## 案詳細（改善案提出スキルが必ず記載）

### 1
提案：bin/capture-plan が画面幅（PC・約400px）の2通りしか撮らないので、画面は広いまま区画だけが狭い状態を1枚も撮らない。区画の中の部品を触ったときは区画幅を変えて撮る枠を足す
担当イシュー：ファイルビュアにエディタ機能を追加
背景：Markdown ブロック編集で、ファイル表示の区画だけを狭めたときにハンドルが区画外へはみ出す不具合を、計画の4枚では再現できなかった
特記事項：memory_improvement/2026-09-28_区画の幅を撮る計画が無い.md に経緯あり。枠を変えると既存の検収記録と並べにくくなるので設計側の判断が要る

### 2
提案：bin/capture-plan が PJT 専用画面とセッション専用画面（各 PC 幅・約400px）の4枚しか出さないので、設定画面など別の画面を触ったときの撮影計画を出せない。触った画面の URL（と、開いた状態を作る操作）を引数で渡せる枠を足す
担当イシュー：ファイル閲覧の上限を設定から変え、大きいものは流し読みする
背景：フェーズ6 で設定画面のカードと確認の窓を検収したとき、capture-plan が使えず、撮るもの（幅2つ×カードと窓）を手で組んで browser_operate に渡した。撮影の係に『カードが見えた状態』と頼むと係が自分でスクロールするので、ハッシュで送る機能の位置の確かめには絵が使えず、DOM で測り直した
特記事項：位置・スクロールのように操作の結果そのものを見たいときは、撮影の係に『自分で送らずに開いたままを撮る』と書くか、DOM の測定を先にする旨を mainflow の段4 に1行添えるのも候補

### 3
提案：capture-plan の3つ目の引数を「PJT のパス」にし、URL エンコードして PJT 専用画面の URL を組む。いまは「プロジェクト名」をそのまま /p/<ホスト>/<名前> に入れるが、この画面の URL は PJT のパスを URL エンコードしたもの（/p/local/%2Ftmp%2F…）で、名前や PJT の ID を入れると「<ID> を開けません（No such file or directory）」になり、ファイルのパネルもセッションも空で写る
担当イシュー：ファイル閲覧の上限を設定から変え、大きいものは流し読みする
背景：2026-11-23 のフェーズ8-B の目視で、capture-plan の出した URL（PJT の ID で組んだもの）を撮影の係へ渡したところ、PJT 専用画面が開けず、係がパスを URL エンコードした URL へ直して進めた
特記事項：無し

### 4
提案：web だけを直したときに、実行ファイルを建て直さずに見た目を確かめる道を持たせる。rust-embed の debug-embed で web は実行ファイルに焼き込まれるので、建て直さないと画面に効かないが、共有ツリーに他のセッションの書きかけ（server/ の未コミット）があると建て直せない。ヘッドレスの Chromium（Playwright）で、走らせたダッシュボードの画面の /assets と文書の要求だけを新しい web/dist に差し替えて測る道具（例：イシューのスクラッチパッドの phase8/tools/dialog_fit.cjs の形）を bin に置き、寸法（窓の高さなど）を数で確かめられるようにする
担当イシュー：ファイル閲覧の上限を設定から変え、大きいものは流し読みする
背景：2026-11-23 のフェーズ8-B で確認の窓のクラスを直したとき、並行のセッションの書きかけ（core/src/lib.rs など）があり release を建て直せなかった。差し替えて測る形で、直す前 772px・直した後 154px を確かめられた（Windows Chrome の絵は次のビルドまで撮れない）
特記事項：字の形は Windows Chrome と違うので、はみ出しや折り返しの判定には使えない。寸法・有無・数の確かめに限る
