## 段1：軽い振り返り（fork）
`subagent_type: "fork"` で現在の会話をそのまま引き継がせ、「今回の作業中に、直さずに見送った改善の種が他に無いか」を軽く振り返らせる。

- 見つからなければ「無し」とだけ返させて終わる。**「無し」が多数派の結果になるのが正常**——毎回何かひねり出そうとしない
- 見つかった場合は、1件につき次の4項目を短く言語化させる：提案・担当イシュー（無ければ「無し」）・背景（無ければ「無し」）・特記事項（無ければ「無し」）

## 段2：書き先を決める
段1で見つかった提案ごとに、書き先を1つに決める。

- 提案の内容が既存のどれか1つのスキル（`.claude/skills/<名前>/`）に関する話だと分かる → そのスキル自身の `PROPOSAL.md`
- 特定のスキルに絞れない、PJT 横断の話 → `.claude/skills/PROPOSAL.md`

**両方には書かない。** 迷う場合は「そのスキルのディレクトリだけを直せば話が済むか」を問いにする。済むなら前者、済まないなら後者。

## 段3：追記（worker）
段2で決めた提案ごとに、`subagent_type: "general-purpose"`、`model: "sonnet"` の worker を1体立てて `bin/append-proposal` を実行させる。

worker への指示に含めるもの：
- 追記先の絶対パス（段2で決めたもの）
- `--session` に現在の `${CLAUDE_SESSION_ID}`
- `--proposal` / `--issue` / `--background` / `--note` の4項目（段1で言語化したもの。無い項目は渡さなくてよい——スクリプト側が「無し」で埋める）
- 「実行結果を検分してから、成功なら『完了』とだけ返せ。失敗したら理由を含めて返せ」

worker 側が守ること：
- **`subagent_type: "general-purpose"`、`model: "sonnet"` はこの段の実行そのものにも適用される**——上位モデルへ勝手に格上げしない
- `append-proposal` の終了コードを確かめてから完了を報告する（0以外なら握りつぶさず理由ごと返す）。**`claim` が取れないときは少し待って再挑戦し、それでも取れなければ排他なしで終了する——「握られていて進めない」と「自分の引数エラー」は別の終了コードで返る**
- `append-proposal` は排他を取った後も、書く直前に宛先ファイルの存在を読み直す（他所が直前に作った／書いたかもしれないため）。worker 側で二重に確認する必要はない
- 変更ログ欄には一切書かない（そこは `proposal_maintain` と各スキルの自己進化ルーチンの領分）

提案が複数件あるときは、1件ずつ（1つの worker が1つの宛先ファイルに対して1件を追記する）実行する。同じ宛先ファイルへ複数件を書く場合も、並行に投げず直列に行う（`claim` は排他を提供するが、# の採番を毎回「既存の最大＋1」で読み直す都合上、直列の方が単純で確実）。
