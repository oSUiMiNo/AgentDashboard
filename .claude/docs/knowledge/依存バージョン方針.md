# 依存バージョン方針

---
<br/>
<br/>

## 完全一致でピン留めするもの
### @xterm/xterm と @xterm/addon-webgl
`@xterm/xterm` 6.0.0 と `@xterm/addon-webgl` 0.19.0 は**キャレット付きレンジを使わず完全一致で固定する**。

理由：addon 側が peerDependencies を宣言していないため、本体とアドオンのメジャーがずれても npm は警告を出さない。片方だけが上がると実行時に壊れる形で初めて気づくことになる。`@xterm/addon-fit` 0.11.0 も同じ理由で完全一致にしている。

更新するときは3つを同時に、同じリリース世代のものへ揃えること。

## レンジで許容するもの
### @tanstack/react-virtual
`^3.14` 系を使う。トランスクリプト表示で必要な末尾追従（`anchorTo: 'end'` + `followOnAppend`）は、依存先の `@tanstack/virtual-core` 3.16.0 で入った機能。

注意点：**この2つはバージョン番号の系列が別**。`react-virtual` 3.14.8 が `virtual-core` 3.17.6 を要求するという関係になっており、「react-virtual を 3.16 以上にする」という読み方は誤り。確認したいときは `npm view @tanstack/react-virtual@<版> dependencies` で virtual-core 側の版を見る。

### axum
0.8 系。設計が前提にしているゼロコピー配信は、WebSocket の `Message` が `Bytes` ペイロードを持つ世代であることに依存している。axum 0.8.9 は `tokio-tungstenite` 0.29 を引いており条件を満たす。

依存の更新時は次のコマンドで世代を確認すること。
```
scripts/cargo tree -i tokio-tungstenite -e normal
```

## 使うフェーズまで入れないもの
motion / shiki / react-diff-view のように、実装フェーズが先のライブラリは**その時点で追加する**。先に入れておくと、使う頃には想定バージョンが変わっており、未使用のまま古い版を抱えることになるため。

実際に motion は フェーズ4（見た目の仕上げ）で 12.43.0 を追加した。方針どおり、使う段で最新版が入っている。

## shadcn/ui のコンポーネントは使うものだけ置く
`npx shadcn add` は指定したぶんだけファイルを生成する。**使わなかったものはその場で消す**こと。
生成物は自分のリポジトリのコードとして残る（node_modules ではない）ので、放っておくと
「どれが実際に使われているのか」が分からないコードが増えていく。

フェーズ4では card / tabs / separator を生成したが使わなかったので削除した。tabs を使わなかったのは、
Radix の Tabs が非選択のパネルをアンマウントするため — 本PJTは**両方のビューを常にマウントしたまま隠す**
（端末を作り直すとスクロールバックが消える）ので、そのままでは前提が合わない。

## cargo-nextest を採用した判断
標準の `cargo test` ではなく `cargo nextest` を使う。

採用理由：テストごとにプロセスを分離し、個別にタイムアウトを掛けられる。本PJTは PTY を扱うテストが増えていくため、1本がハングしたときに全体を巻き込む事故を防げることの価値が大きい。導入コストはプリビルドバイナリを Docker イメージに置くだけで済む。

`cargo test` も引き続き動くので、nextest が使えない状況でも詰まらない。
