いま動いているもの

AgentDashboard に関係して、この機械や外で起動しっぱなしになっているものの一覧。 「どの URL がどれを指しているか」を取り違えると原因追跡が丸ごと空振りするので、そこを中心に書いてある。
最終更新：2026-08-05（3台とも 0.1.3 を名乗るが、手元の2台と AWS は中身が違う）

先に用語

このプロジェクトを知らないと意味が取れない言葉だけ並べる。以降の説明では必ずこの名前を使い、▽ を付ける。

言葉意味
ローカルモードダッシュボードと「PC 側の一式」が1つのプロセスに同居する動かし方。落とすと、走っている claude も道連れで死ぬ
サーバモード--mode server で起こす動かし方。擬似ターミナルを持たず、ブラウザへの配信だけを受け持つ。落としても、繋がっている PC のセッションは死なない
PC 側エージェントagentdashboard-agent。利用者の機械に常駐し、claude を擬似ターミナル上で動かして、サーバへ報告する
Cloudflare Tunnel手元の待ち受けポートに、インターネットから届く URL を割り当てる仕組み。ここでは使い捨ての trycloudflare.com を使っている
ソースビルド配布物を取ってこず、リポジトリで make build して出来た実行ファイルを直接起こすこと。リリースを出しても、この動かし方には何も届かない

全体の見取り図

四角が動いているもの、矢印が「どこを指しているか」。

いちばん間違えやすいところ。 この機械にも cloudflared tunnel --url http://127.0.0.1:8788 が動いているので、 ps で見ると「あの URL は 8788 だな」と読めてしまう。 実際は別物で、普段見ている flying-playback-not-lang.trycloudflare.com は AWS EC2 側の cloudflared が作った URL。
実際にこれを取り違えて、キャッシュを疑って強制リロードを3通り試す、という遠回りをした。
版番号が同じでも、中身は同じとは限らない。 手元の2台はソースビルド▽なので、版を上げなくても git pull と make build のたびに中身が変わる。 一方 AWS は配った箱なので、リリースを出すまで何も変わらない。
いまは3台とも 0.1.3 を名乗るが、設定の持ち出しが入っているのは手元の2台だけ。 画面に出る版だけを見て「同じものが動いている」と判断しないこと。

AWS EC2 について

  • 箱（コンテナ）で動いているので、版のドロップダウンは出ない。「compose.yml の image: を書き換えて」という案内のカードだけが出る。壊れているのではなく、そう作ってある（設計§14）
  • 更新は SSH で入って3行——compose.yml の image: の版を書き換え、sudo docker compose pull、sudo docker compose up -d。記録（PostgreSQL）は別の箱なので消えない
  • 手元の AWS 認証情報は失効しているので、CLI から状態を問い合わせられない。生きているかどうかは、上の URL が応答するかで判断する。SSH は通る（鍵は ~/Dev/Test_AgentDashboard/ssh_key.pem）
  • t3.small で概ね4円/時。残す判断を取っているので、勝手に壊さないこと
  • 止めるときは ~/Dev/Test_AgentDashboard で terraform destroy。ただし利用者の明示的な承認が要る

更新の約束

残す基準はひとつ。「次に触る人がこれを知らずに動くと事故るか」。 是なら書き、否なら書かない。ここは「いま」だけを持つ場所で、履歴は積まない。

大きな作業が一区切りついたら見直す

作業の途中経過は流さない。動いている最中の状態を書いても、次に読む人が見る頃には嘘になっている。

したことここへの反映
常駐するものを起こした／起こし直した行を足す・版を書き換える
常駐するものを落としたその行を消す
トンネルを張った／張り替えたURL とその先を対で書く。古い対応は消す
外に何かを立てた／壊した立てたら足す。壊したら消す
ログの出力先や設定の場所を変えたいまの場所へ書き換える

足すより、消すほうを忘れやすい

役目を終えたもの——落としたプロセスの行、壊した環境の項、戻した設定の注記——は、 その場で消すか、いまの姿へ書き換える。「前はこうだった」は残さない。それは各イシューの実行レポートの仕事。

迷ったら分量で気づく。ここが増える一方なら、実行レポートに書くべき粒度が混ざっている合図。 開いて数十秒で現状が掴めなくなった時点で、書きすぎている。

書くのは「何が・どこで・どの版で・どう起こしたか」の4つだけでよい。

なぜ「版」を必ず書くのか。 ソースビルド▽で動かしているものは、リリースを出しても何も変わらない。 更新するには git pull → make build → 起こし直す、が要る。 「リリースしたのだから最新のはず」という思い込みが、いちばん時間を溶かす。
