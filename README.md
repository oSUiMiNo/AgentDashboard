# AgentDashboard
複数プロジェクト・複数セッションの Claude Code を一望する、個人用の司令塔ダッシュボード。Web アプリとして提供し、ブラウザから閲覧・操作する。

自分の PC 1台で完結させることも、サーバを1台立てて**複数の PC を集める**こともできる。後者なら、外出先のスマホから家の PC のセッションを見て操作できる。

## これは何か
Claude Code を並行して何本も走らせていると、セッションごとにターミナルが散らばって「いまどれが動いていて、何をしていて、権限確認で止まっていないか」が分からなくなる。かといって Claude アプリの見やすい履歴表示に移ると、`/rewind` のようなターミナル専用のスラッシュコマンドが使えない。

AgentDashboard は**その両方を同時に成立させる**ことを目的にしている。

中心にあるのは「**実行は本物のCLI、表示は構造化UI**」という考え方だ。

```
ブラウザ（ダッシュボード）
 ├─ 構造化ビュー … JSONL + フック通知から組み立てる（Claudeアプリ風のネスト表示）
 └─ ターミナルビュー … 本物の画面をそのまま表示（/rewind 等の対話操作用）
        ↑↓ WebSocket
サーバ（Rust 単一バイナリ）
 ├─ PTY 上の本物の claude CLI（入力はすべてここへ行く）
 ├─ JSONL トランスクリプトの監視（別プロセスのパーサ）
 └─ フック受信（状態をプッシュで受け取る。ポーリングしない）
```

サーバは擬似ターミナル（PTY）の上で**本物の claude CLI** を起動する。実体がターミナルの Claude Code そのものなので、`/rewind` を含むあらゆるスラッシュコマンドが制約なく使える。

一方、画面はターミナル出力（ANSI）の解析では作らない。Claude Code が常時書き出す構造化トランスクリプト（JSONL）とフックイベントから組み立てる。ANSI 画面のスクレイピングは脆く、そして必要が無い。

この二層構成には縮退したときの利点もある。ターミナルビューは JSONL のフォーマットに依存しないので、**構造化ビューが壊れてもターミナルとしては使える状態が常に残る**。

### 主な機能
- **一覧（司令塔ビュー）** … プロジェクト（PJT）の枠ごとに小窓をまとめ、全セッションの状態・最終活動からの経過時間・サブエージェントの稼働数・セッション名を一望する。**状態は枠線の色と動きで出る**（作業中は回り、承認待ちは揺れる）
- **PJT の枠** … セッションの有無に関係なく PJT を追加できる。枠は閉じても消えず、「×」を押したときだけ消える
- **PJT 専用画面** … その PJT のセッションを横並びで見比べつつ、**左のパネルでフォルダを辿ってファイルを読める**（相対パスのコピー・Markdown の整形つき）
- **セッション専用画面** … 「サブエージェント → ツールコール → 編集差分」と掘っていける構造化ビューと、本物の画面そのままのターミナルビューを切り替えられる
- **指示送信** … 自然文でも任意のスラッシュコマンドでも、専用画面から送れる
- **自己修復** … JSONL のフォーマットが変わったことを検知し、パーサを自分で直してテストに通ったら差し替える
- **版の切替** … 新しい版を取ってきたり、前の版へ戻したりを画面から行う。**選んだ瞬間には何も起きない**（効くのは次に起こしたとき）

## 前提
使うだけなら、要るのは**本物の `claude` と認証**だけ。ダッシュボードが PTY 上で起動する対象そのものなので、動かす機械に入っている必要がある。

そのうえで、次の2つは「あると効く」もの。

| もの | 何のために |
|---|---|
| Docker | セルフホストを compose で運用する場合。**必須ではない**——サーバは同じ実行ファイルを `--mode server` で起こすだけでも立つ |
| **本リポジトリのソース一式**＋Docker＋Git | 自己修復。パーサを書き換えてビルドし直すので、**ソースの無い場所へバイナリだけ置くと検知の通知だけになる**（[既知の制約](#配布したバイナリでは自己修復が検知だけになる)） |

動作を確認しているのは Linux（WSL2 上の Ubuntu 24.04）。

## セットアップ
```
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/oSUiMiNo/AgentDashboard/releases/latest/download/agentdashboard-installer.sh | sh
agentdashboard
```

ブラウザで **http://127.0.0.1:8787** を開く。`~/.local/bin` へ3つ入る——ローカル用の `agentdashboard`、セッションホストの `agentdashboard-agent`、履歴を読む `transcript-parser`。**3つは隣同士に置いたままにすること**（互いを隣で探す）。

使い方は目的で分かれる。

| したいこと | 読むもの |
|---|---|
| 自分の PC 1台で使う | [ローカルで使う](docs/setup/local.md) |
| サーバを立てて複数の PC を集める | [セルフホストで使う](docs/setup/selfhost.md)（**立て方は2つ**——実行ファイルだけ／docker compose） |
| PC をサーバへ繋ぐ | [ペアリング](docs/setup/pairing.md) |
| インターネットから使う（TLS） | [リバースプロキシ](docs/setup/reverse-proxy.md) |
| 消す | [消す](docs/setup/uninstall.md)（**記録は既定では消しません**） |

### ソースから建てる
自己修復を動かすならこちら（開発するときも同じ）。

```
git clone https://github.com/oSUiMiNo/AgentDashboard.git
cd AgentDashboard

make setup                          # Docker イメージ・npm・Playwright の chromium
cp server/config.toml.example config.toml   # 全キーに既定値があるので、そのままでも動く
make build                          # web をビルド → 単一バイナリへ同梱

./server/target/release/agentdashboard
```

`config.toml` は**リポジトリルート**（＝起動時のカレントディレクトリ）から読む。別の場所を使うなら `--config <パス>` で指定する。

### 動かしてみる
1. 一覧の「**PJT を追加**」を押し、フォルダを辿って選ぶか、**作業ディレクトリのパス**を打ち込む（[受け付ける形](#作業ディレクトリの入力は多めに見る)は絶対パスだけではない）
2. できた枠の「**＋**」を押してセッションを起こす（権限モードはここで選ぶ）
3. 初めてのフォルダなら、ターミナルビューにフォルダ信頼の確認が出るので **Ctrl+Enter** で答える
4. 下の入力欄から指示を送る（**Ctrl+Enter で送信** / Enter で改行）

枠を足すたびにセッションも1本起こしたいなら、設定画面の「PJT を追加したらセッションを起こす」を ON にする。

## 使い方

### 一覧画面
並ぶのは **PJT の枠**で、その中にセッションの小窓が入る。枠は「PJT を追加」で足し、「×」で外す。**セッションが1本でも走っている枠は外せない**（走っている作業を巻き添えにしないため。押せない理由は画面に出る）。

**セッションが居る枠が上、居ない枠が下**に並ぶ。群の中の並びは追加した順で固定してあり、状態が変わっても動かない——押そうとした瞬間に的が逃げないようにするため。

小窓の主役は**ログの縮小表示ではなく状態インジケータ**。「AI が止まらずちゃんと働いているか」を一瞥で確かめるための画面なので、状態の色と最終活動からの経過時間を最も大きく出している。

状態は**カードの枠線が光る色**で表す。色は**役割ごとに固定**してあり、足りないぶんは**記号**で分ける——1つの画面で色だけに頼って見分けられるのは6色までで、しかも赤や琥珀を警報以外へ広く使うと警報が効かなくなるためだ。記号は状態ラベルの手前に置く。

| 状態 | 印 | 色 | 役割 | 枠線の動き | 何が起きているか |
|---|---|---|---|---|---|
| 作業中 | `⟳` | シアン | 進行中 | 速く回る | ツールを実行し続けている |
| 停滞 | `‖` | シアン（弱） | 進行中 | **遅く**細く回る | 作業中のままイベントが一定時間途絶えた |
| 入力待ち | `▶` | 琥珀 | 保留 | ゆっくり明滅 | ターンが終わって指示を待っている |
| 権限確認待ち | `!` | 琥珀 | 保留 | **ときどき揺れる** | 人が答えないと先に進まない |
| 起動中 | `◌` | 灰 | — | 動かない | 起動はしたが最初のフックがまだ届いていない |
| 終了 | `✓` | 灰 | — | 動かない | セッションが終わった |
| 異常終了 | `✕` | コーラル | エラー | 動かない | セッションが異常終了した |
| 不明 | `?` | コーラル | エラー | 動かない | 状態を判断できない。フック未受信ならその旨を名指しする |

**色で読めるのは「進行中／注意・保留／エラー」の3段まで**で、その中のどれかは記号が答える。「あなたの番かどうか」を色が、「どちらの番か」を記号が示す。

**終わったものと、まだ始まっていないものは、どちらも灰で静かにしてある。** どちらも対処が要らないうえ、**一覧でいちばん数が多くなるのは終了**なので、ここへ強い色を当てると画面がそれで埋まる。区別は記号（`◌` と `✓`）が受け持つ。

**進行中のカードだけ、中身にうっすら色が敷かれる。** 一覧で「いま動いているもの」を面で拾えるようにするためで、他の状態には敷かない。

**人が答えないと進まないカードには、`ANSWER` のステッカーが貼られる。** 全部の状態に付けると表の1列になって目を引かなくなるので、**この1状態にだけ**貼っている。

**承認待ちのカードだけは、その場で小さく跳ねる。** 人が答えないと先へ進まない唯一の状態なので、他と同じ見せ方にしていない。跳ねるたびに短い線が2〜3本だけ飛び出し、**画面をしばらく回遊してから消える**（同時に出るのは最大10本）。マウスを近づけると鎮まり、その瞬間に線が数本だけ外へ飛ぶ。**並びは動かさない**ので、押そうとした的が逃げることはない。

経過時間を必ず並べているのは、**「作業中」の表示のままハングしているケースを見逃さないため**。状態のラベルだけでは、動いているのか固まっているのかが区別できない。

いちばん下には**セッション名**（`--resume` の一覧に出るもの）が1行で出る。名前は最初のターンのあとに付くので、**起こした直後は空**（行の場所だけが残る。付いた瞬間にカードの高さが動かないようにするため）。**直前の応答は、変わった直後だけ**その上に1行だけ足される（12秒で消える）。

#### 動きを止める
設定画面の「一覧の動き」で3段から選べる。既定は**賑やか**。

| 段 | 何が止まるか |
|---|---|
| 賑やか（既定） | 何も止めない |
| 控えめ | **作業中の回転**と**画面を回遊する線**が止まる。停滞・入力待ち・承認待ちのカードは動いたまま |
| 静止 | すべて止まる。**色・記号・文字は残る**ので状態は読める |

OS の「動きを減らす」を入れている場合は、**段の選択によらず止まる**。

### 作業ディレクトリの入力は多めに見る
本アプリは WSL の上で動くので、パスは Windows 側のエクスプローラから貼られることがある。「PJT を追加」の打ち込み欄は次の形をどれも受け取る。

| 入力 | 開かれるフォルダ |
|---|---|
| `/home/example/dev/app` | そのまま |
| `\home\example\dev\app` | `/home/example/dev/app` |
| `home/example/dev/app`（先頭の区切り忘れ） | `/home/example/dev/app` |
| `\\wsl.localhost\Ubuntu-24.04\home\example\app` | `/home/example/app` |
| `C:\Users\me\proj` | `/mnt/c/Users/me/proj` |
| `"..."` で囲まれたもの（「パスとしてコピー」） | 引用符を外したもの |

**入力そのままの解釈を必ず先に試す**ので、`\` を名前に含む実在のフォルダも今までどおり開ける。読み替えた先も見つからなかった場合は、エラーに「何として解釈したか」が併記される。

なお `\\wsl.localhost\<ディストリ>\...` の**ディストリ名は照合していない**。別のディストリの中身はここからは見えないので、違う名前を貼れば「存在しません」として落ちる。`~` の展開はしない。

### 権限モード
セッションは**どのくらい確認を出すか**を選んで起動できる。枠の「＋」を押したときに出る選択で選ぶ。

| 選択肢 | 渡すもの |
|---|---|
| スキップの指定は無し | **何も渡さない**。あなたの `permissions.defaultMode` がそのまま効く |
| 編集の承認のみスキップ | `--permission-mode acceptEdits` |
| 全承認をスキップ | `--permission-mode bypassPermissions` |

設定画面のトグルを ON にすると、**既定の選択**が「全承認をスキップ」になる。選択肢は3つのままなので別のモードでも起こせるが、**起動するたびに既定へ戻る**——前回の選択が残って、意図しないモードで次の1本を起こすことがない。

いまのモードは**小窓とセッション画面の両方**に出る。危険なモードほど目立つ色で出るので、全承認をスキップしているセッションが一覧に埋もれない。

セッション画面のプルダウンから切り替えられる。実体は TUI への Shift+Tab なので、**行けないモードがある**（下記の制約）。

### モデル
セッションが**どのモデルで動いているか**が、小窓とセッション画面の両方に出る。表示は
`Opus 5` のように**版番号つき**で、これは CLI が名乗った名前をそのまま出しているため。

セッション画面のプルダウンから切り替えられる。切替は**そのセッションだけ**に効く。

```
Opus 5                ← いま動いているモデル
──────────
既定 / 最良 / Fable（Fable 5）/ Opus（Opus 5）/ Sonnet / Haiku / …
                      ← 切り替え先。括弧は一度選んだことがある別名にだけ付く
```

版番号を**こちらの表に書いていない**のは、別名がどの版に解決されるかが環境で変わるため
（`opus` は Anthropic API なら Opus 5、Microsoft Foundry なら Opus 4.6）。
名前は次の順で、確かなものから決まる。

1. その別名で切り替えて CLI が名乗った値（実測）
2. **起動している claude 自身が持っているモデル表**から引いた「その系統の最新」
3. 何も分からなければ別名のラベル（`Opus`）

2 のおかげで、**一度も選んでいない別名にも版番号が出る**。`既定` `最良`
`プラン=Opus / 実行=Sonnet` に版番号が付かないのは、解決先が状況で変わるから——
`最良` を `Fable 5` と出すと `Fable` と見分けが付かなくなる。

選択肢にマウスを乗せると、それぞれが何をするのかが出る。

#### 他のセッションは巻き込まれない
`/model` は CLI にとって「ピッカーで Enter を押した」のと同じ扱いで、**選択をあなたの
`~/.claude/settings.json` へ保存する**。放っておくと、次に起こしたセッションもそのモデルで
始まってしまう。

ダッシュボードは二段構えで防いでいる。

1. セッションを起こすときに、覚えているあなたの既定モデルを**注入する**
2. 切替のあと、汚れたグローバル既定を**元へ戻す**

戻すときに触るのは `model` キーだけで、他のキーも並び順もインデントも動かさない。
**あなたが自分でグローバル既定を変えた場合は戻さない**（新しい既定として覚え直す）。

#### モデルを変えると権限モードが変わることがある
`auto`（自動）で動いているセッションを Haiku へ切り替えると、権限モードが
`手動確認` へ落ちる。Haiku が `auto` の対象外だからで、CLI 側の仕様。
ダッシュボードは実態どおりに表示を訂正するだけで、隠さない。

#### あなたの `statusLine` は上書きされる
モデル名を知る経路が `statusLine` しかない（既定のフッタにモデル名は出ない）ので、
ダッシュボードが起こしたセッションでは**こちらの `statusLine` が勝つ**。
自分のものを優先したい場合は `inject_status_line = false` にする——ただし
モデルの表示は「不明」のままになり、切替もできなくなる。

#### 別名の一覧は自動で追随する
Claude Code のバージョンが上がると、ダッシュボードは2つを自動で見直す。

| 何 | どうやって |
|---|---|
| 正式名と通称の対応（`claude-opus-5` → `Opus 5`） | 起動している claude バイナリから読む。0.2秒・無料 |
| 別名のラインナップと説明文 | **無人のセッションを1本起こし、公式ドキュメントを読ませて表を更新させる** |

後者は `web/src/lib/models.ts` の1ファイルだけを書き換える。触った範囲・表の形・
使用中の別名が残っているか・型検査とテストが通るかを機械で確かめ、1つでも駄目なら
採用せずに捨てる。`selfheal_enabled = false` なら動かない。

**同じバージョンでは二度と起こさない**（成否によらず）。次のバージョンで再挑戦する。

#### 引き継いだセッション
`--resume` で引き継いだセッションも、注入した既定で始まる（実測）。公式ドキュメントは
「トランスクリプトのモデルを引き継ぐ」と書いているので、CLI 側の変更で覆る可能性がある。
覆っても表示は CLI が名乗った値なので、**画面が嘘をつくことはない**。

### クリックの作り分け
- **小窓をクリック** → そのセッションだけの専用画面（`/s/:cardId`）
- **枠の余白をクリック** → その PJT の専用画面（`/p/:host/:project`）。全セッションが**横並び**になる。兄弟セッションを見比べるとき用
- **セッションが0本の枠**でも同じ画面が開く。そこには「＋」だけが出る

URL に PC（`:host`）が入るのは、**同じパスが別の PC にもありうる**ため。1台だけで使っているときは意識しなくてよい。

### 行った先から、行き来できる
一覧から入ったあと、**ブラウザの戻るを使わずに隣の画面へ移れる**。

| どこで | 何を押すと | どこへ |
|---|---|---|
| セッション専用画面 | 上に出ている**作業ディレクトリのパス** | その PJT の専用画面 |
| PJT 専用画面の各区画 | タブの左の「**開く**」 | そのセッションの専用画面 |

**押す先は文字**にしてある。**「移る」（決まった行き先へ進む）と「戻る」（前の画面へ帰る）を、形の種類で分ける**ためで、色や位置では分けていない——色は暗いところで差が縮み、位置は画面の幅で変わるためだ。

一覧へ帰るときは、いままでどおり「一覧へ戻る」を押す。

### PJT 専用画面のファイル
左上の**サイドバー**のボタン（**枠の中に左寄りの縦線**が1本。☰ ではない——「左の区画を出し入れする」ことをそのまま描いてある）を押すと、画面の左にその PJT のフォルダが出る。この左から出てくる区画のことを、この文書では**サイドバー**と呼ぶ。エージェントへ渡すパスを作るための道具で、次の3つができる。

| したいこと | どうなるか |
|---|---|
| パスを渡す | 「パスをコピー」で **PJT のルートからの相対パス**が取れる（何からの相対かは画面に出る） |
| 進捗を見る | `.md` は整形して出る。**チェックボックスの入り／未入りがそのまま読める** |
| 中身を疑う | 「生テキストで見る」で、整形前のそのままが読める |

**辿れるのは PJT のルートより下だけ**（相対パスの基準が壊れるため。これは画面の作法であって、口そのものの制限ではない）。**書き換えはできない**——読むだけの道具で、直したいならセッションへ指示を送る。

生の HTML は**整形しても字面としても出さない**——**ただし `<br/>` だけは改行として出る**。このリポジトリのドキュメントは節の区切りに `<br/>` を置く作法なので、**その行間はそのまま見える**。それ以外のタグ（`<span>` など）は行ごと消えるので、何が書いてあったかは「生テキストで見る」で確かめられる。

#### 開ける大きさには上限がある
**超えたら黙って切らずに断る**（切った先頭だけを出すと、そこで終わっているように読めるため）。断り文には実際の大きさが出る。

| 何を | 上限 |
|---|---|
| テキスト（`.md`・生テキスト・**HTML と SVG も**） | **3 MiB** |
| 画像（`.png` `.jpg` `.jpeg` `.gif` `.webp`） | 8 MiB |

**HTML と SVG は画像側ではなくテキスト側の上限で決まる。** 絵として描くときも中身はテキストとして運んでいるためで、`iframe` で描くか字面で読むかによらず同じ線が効く。

#### 大きい `.md` は、整形せずに出る
**256 KiB を超える Markdown は、整形せずに生テキストで始まる。** 整形は**開いた端末のブラウザの中で**走り、大きさに対して**倍では済まない伸び方**をするので、そのまま流すと画面が固まる。生テキストのほうは大きさによらず一瞬で出る。

**どれくらい重いかは端末で変わる。** 負担を払うのは開いた端末なので、**スマホでは PC より重い**。256 KiB という線は「そこまでは実際に毎日使われていて問題が出ていない」大きさから引いてあり、**実機のブラウザで測り直した値ではない**。

**禁じてはいない。**「整形して見る」を押せば整形する——300 KiB の文書なら数秒の話なので、待つかどうかは押す人が決める。整形せずに出したときは、その理由が画面に出る。

**この線が掛かるのは `.md` だけ。** HTML と SVG は `iframe` の中でブラウザ自身が描くので、大きくてもそのまま描かれる。

サイドバーの開閉は覚えているので、次に開いたときも同じ状態で始まる。

**広い画面では、サイドバーは被さらずに右を押しのける。** ファイルを選んでも閉じない道具なので、開いたまま読む時間が長い——被さっている限り、その裏はずっと読めないままになる。

**狭い画面では被さるが、全画面にはしない。** 幅は 320px ほどで、**裏は必ず15%以上見えている**。あわせて画面全体が半分の暗さになるので、「被さっている」のか「別の画面へ移った」のかを取り違えない。閉じ方は2通り——**サイドバーの中の閉じるボタン**と、**暗くなったところを押す**。

サイドバーとファイルの中身は、**境目をつまんで幅を変えられる**（変えた幅は覚えている）。**狭い画面には境目が出ない**——あちらでは中身の列がセッションの小窓と同じ幅で扱われ、**セッションと一緒に横へ流れる**ので、つまんで変える対象にならない。

### セッション専用画面
| タブ | 何をするところか |
|---|---|
| 構造化ビュー | 履歴を「あなた → アシスタント → ツールコール → 編集差分」と掘っていく。サブエージェントは起動元のツールコールの子として入れ子で出る |
| ターミナル | 本物の画面そのまま。`/rewind` のようにメニュー操作が要るときはここを触る |

下部の入力欄はタブと独立して常設で、どちらを見ていても指示を送れる。複数行はそのまま1つの指示として届く。

#### 打った改行は、打ったとおりに出る
本文はマークダウンとして整形して出すが、**行の途中の改行もそのまま改行にする**。マークダウンの決まりでは、空行を挟まない改行は前後が空白1つで繋がる——壊れているのではなく正しく出た結果だが、**打った側の見た目とは食い違う**。ここは打った側に合わせてある。

**扱いは構造化ビューとファイル閲覧で同じ**なので、同じ字を貼れば同じ見え方になる。囲みコードブロックと表の中は変わらない（もともと改行がそのまま出る場所なので、二重にはならない）。

**`<br/>` を書いた直後にさらに改行を打つと、改行2つぶんになる。** 打った側から見れば2つ書いているので、そのまま出すほうへ倒してある。

#### 端末の大きさは、見ている画面では変わらない
ターミナルは **120桁×40行に固定**してある。**見ている端末の広さで桁行を決めない**ので、PC とスマホで同じセッションを開いても互いの表示を作り替えない（以前は後から開いたほうが勝っていた）。

入りきらないぶんの見せ方は、横と縦で違う。

| 方向 | どうなるか |
|---|---|
| 横 | **端末の中を横スクロール**して読む（スマホでは横へ払う） |
| 縦 | **下端に貼り付けて、上を隠す**。隠れた行は指でなぞって遡れる |

読みたいものが必ず下にあるので（選択肢は末尾に出る・プロンプトも下端）、切り落とすのは常に上側にしてある。広い画面では逆に**格子より入れ物が大きくなる**ので、上に地の色の余白ができる。

**Enter まわりは入力欄とターミナルで同じ割り当てにしてある。**

| キー | 何が起きるか |
|---|---|
| Enter / Shift+Enter | 改行 |
| **Ctrl+Enter** | **送信** |

同じ画面に入力口が2つあるので、押し分けが食い違うと「いまどちらに焦点があるか」で結果が変わってしまう。ターミナル側では**選択ダイアログの確定も Ctrl+Enter** になる（フォルダ信頼の確認など）。

### 版を切り替える
設定画面（`/settings`）の「ダッシュボードの版」から、**新しい版を取ってきたり、前の版へ戻したり**できる。最新の版が微妙だったときに戻れるようにするための機能なので、**手元に持っている版のあいだでしか切り替えない**。

#### 選ぶことと、効かせることは別
ドロップダウンで選んでも、**その瞬間には何も起きない**。動いているセッションも表示もそのままで、選んだ版が効くのは**次に起こしたとき**。

```
いま動いている版  0.1.2  /home/example/.local/bin/agentdashboard
次に起こす版      0.1.1 ▼          ← 選んだだけの状態（予約）

  0.1.1 を予約しています。次に起こしたときから効きます。
  いま入れ替えると 3 枚が抜け殻になります（履歴は残りますが、操作はできなくなります）。
  [いま入れ替える]  [予約を取り消す]
```

すぐ反映したいときだけ「いま入れ替える」を押す。**ここでだけ**プロセスが落ちる——ローカルモードでは claude が道連れになるので、押す前に何枚が抜け殻になるかを数で出す。抜け殻になっても**履歴は残る**（読めるが、操作はできない）。

落としたあと誰が起こし直すかは構成による。常駐の設定（systemd の `Restart=always` など）があれば自動で戻ってくる。無ければ端末で `agentdashboard` を実行する。画面にもそう出る。

#### 取ってくる・消す
新しい版が出ていると「新しい版があります」と出るので、**押したときだけ**取ってくる。勝手には取ってこない。

見に行くのは**1日1回**まで（起動のたびに外へ出ないため）。したがって新しい版が出てから知らせが出るまで、**最大1日ほど遅れる**。すぐ知りたいときは、リリースの一覧を直接見るのが早い。

取ってきた版は `<state_dir>/versions/<版>/` に3本まとめて置かれ、`~/.local/bin` の3本は**一度も書き換えない**。使わなくなった版は一覧から消せる（1版あたり30MBほどなので、使用量も出している）。

**いま走っている版は消せない。** 予約している版は消せるが、そのときは**予約も一緒に外れる**（次に起こすと、入れる側が置いた版で立ち上がる）。

#### 古い版へ戻すときに聞かれること
この機能より前の版（`0.1.1` 以前）へ戻すときは、**確認を求められる**。それらの版は「自分がどの記録の形を知っているか」を答えられないので、戻して安全かを確かめようがないため。

そして戻した先には**版を選ぶ画面が無い**ので、画面からは戻ってこられなくなる。確認の画面に、手で戻すための2行が出る。

```
cat  ~/.local/state/agentdashboard/version-current   # いま何を指しているか
rm   ~/.local/state/agentdashboard/version-current   # 入れる側が置いた版へ戻す
```

（`state_dir` を変えている場合はその場所になる。画面には**実際の場所**が出る。）

### 設定を持ち出す
設定画面の「設定の持ち出し」から、**このアカウントの設定をファイルへ書き出し、読み込んで戻せる**。別の端末や別のアカウントへ同じ設定を移すときに使う。

入るのは設定画面で変えられる5つ（権限確認スキップの既定・PJT 追加時の自動起動・履歴の同期間隔・画面の更新間隔・スクロールバック行数）だけ。**LAN のパスワードや、繋いだ PC の鍵といった秘密は入らない**——書き出すのはアカウントに属する設定だけで、それらは別の場所にあるため。

読み込みは**全部通るか、1つも入れないか**。値がおかしければどのキーが駄目かを出して断り、その場合は何も書き換えない。知らないキーは無視するが、無視したことは画面に出る。

読み込んだ設定が入るのは**いまログインしているアカウント**。ファイルに宛先は書かれていないので、他人のアカウントへ入れることはできない。

## ログ
**何もしなくても残る。** サーバもセッションホストも、動いている間ずっと1行1レコードのファイル（JSON Lines）へ書き出している。設定で切ることもできるが、既定は有効にしてある——**動かなくなってから「ログを出す設定にしておけばよかった」と気づいても遅い**ため。

### どこにあるか
`<state_dir>/logs/`。場所は OS と設定で変わるので、決め打ちで覚えずに実行ファイルへ聞く。

```
agentdashboard state-dir
```

ファイルは `<誰が>-<pid>.<日付>.jsonl` の形で、プロセスごと・日付ごとに分かれる。同じ機械で何度も起こし直しても、**どの起動のぶんか**がファイル名で分かる。

### どう読むか
自分で開かずに、読む口を使う。

```
agentdashboard logs --since 1h              # 直近1時間
agentdashboard logs --level warn            # 警告以上だけ
agentdashboard logs --card <カードID>       # 1枚のカードに関わった行だけを串刺しで
agentdashboard logs --grep "見たい語"        # 本文で絞る（正規表現）
agentdashboard logs --json                  # 加工せず生のまま出す
agentdashboard logs --follow                # 出るそばから追いかける
```

複数のファイルに分かれていても**時刻順にひとつながりで**出る。セッションホスト側は `agentdashboard-agent logs` で、使い方は同じ。

### いつ消えるか
古いものは**起動のたびに掃かれる**。既定は7日ぶん、または `<state_dir>/logs/` の合計 512 MiB まで（`log_retention_days` / `log_max_bytes`）。**長く起こしっぱなしの機械では、次に起こし直すまで掃かれない**ので、そこだけ注意する。

### 外へ貼るとき
そのまま貼らない。**`--sanitize` を付ける。**

```
agentdashboard logs --since 1h --sanitize
```

ホームのパス・利用者名・ホスト名・メールアドレス・トークンの類を伏せ字にしてから出す。伏せる規則は**その機械の環境から組み立てる**ので、他人の機械のログには効かない。

## 設定
`server/config.toml.example` が全キーの一覧を兼ねている。**全キーに既定値がある**ので、変えたい項目だけ書けばよい。打ち間違いを黙って無視しないよう、**知らないキーを書くとエラーになる**。

| キー | 既定 | 変えると何が変わるか |
|---|---|---|
| `port` | `8787` | 待ち受けポート |
| `bind_addr` | `127.0.0.1` | 待ち受けるアドレス。**広げると入口の鍵が変わる**——`127.0.0.1` 以外にすると合言葉（LAN パスワード）が要る作りになり、**登録せずに広げると起動を拒否する**。同じネットワークの別の端末やスマホから開くときに使う（[ローカルで使う](docs/setup/local.md)） |
| `stalled_threshold_secs` | `120` | この秒数イベントが途絶えたら「停滞」とみなす |
| `inject_status_line` | `true` | セッションへ `statusLine` を注入するか。**モデル名を知る唯一の経路**なので、切ると表示が「不明」のままになり切替もできなくなる |
| `status_line_refresh_secs` | `3` | `statusLine` の再実行間隔（秒、最小1）。**切り替えた結果が画面へ反映されるまでの時間は事実上この値で決まる** |
| `claude_settings_path` | `~/.claude/settings.json` | あなたのグローバル設定の場所。差し替えるのはテストと E2E のためで、普段は指定しなくてよい |
| `always_bypass_permissions` | `false` | 枠の「＋」で出る権限モードの**既定の選択**を「全承認をスキップ」にする（選択肢は減らない）。**ここに書くのは初期値**で、設定画面（`/settings`）から変えると以後はそちらが正になる |
| `coalesce_ms` | `8` | PTY 出力をまとめてから送るまでの窓。小さくすると遅延は減るがフレーム数と CPU が増える |
| `pty_ring_buffer` | `1048576` | セッションごとの scrollback。ターミナルを開き直したときに遡れる量 |
| `flow_high` / `flow_low` | `262144` / `32768` | フロー制御のしきい値。ブラウザが追いつかないとき PTY の読み取りを止める境目 |
| `transcript_window_nodes` | `2000` | メモリに持つ履歴の直近ウィンドウ。これより古い範囲はパーサへ読み直しを頼む |
| `transcript_page_limit` | `200` | 履歴を遡るときの1回あたりのノード数 |
| `selfheal_enabled` | `true` | 自己修復を動かすか。`false` にすると検知の通知だけを出す |
| `canary_model` | `"haiku"` | 新しい版のサンプルを採るモデル |
| `canary_fallback_model` | `"sonnet"` | サンプルが要素不足だったときに1回だけ採り直すモデル |
| `repair_model` | `"sonnet"` | 修復セッションのモデル |
| `selfheal_retry` | `3` | 修復の再試行上限 |
| `selfheal_cooldown_hours` | `24` | 同じ版へ再挑戦するまでの間隔 |
| `selfheal_repo_dir` | 自動探索 | ダッシュボード自身のソース。未指定ならカレントから上へ辿って探す |
| `state_dir` | `~/.local/state/agentdashboard` | 再開位置・自己修復の対応表・差し替えたパーサの置き場所 |
| `log_retention_days` | `7` | ログを残す日数。これより古いものは起動時に消える |
| `log_max_bytes` | `536870912`（512 MiB） | `<state_dir>/logs/` の**合計**の上限（バイト）。1ファイルの上限ではない。超えていたら古い順に消す |
| `log_file_level` | `"debug"` | ファイルへ残すレベル。**端末に出る量はこれではなく `RUST_LOG` で決まる** |
| `revive_estimate_mb` | `780` | 起こし直し1枚あたりで減る空きメモリの見積もり。**「全て復旧」が入るかどうかを数えるのに使う**（実測値。機械と MCP の載せ方で変わるので動かせる）。`0` にすると数えない |
| `revive_headroom_mb` | `2048` | 起こし直しで使い切らずに残す余白。**空きを 0 まで使うと、戻したあとに何も動かせない機械が残る** |

解決後の値は `agentdashboard config` で確認できる。

## 既知の制約
道具として使う前に知っておいたほうがよいものを挙げる。

### ローカルモードでは、再起動すると全セッションが終了する
claude の PTY はダッシュボードの子プロセスなので、落とすと道連れになる。**落とさない運用**が前提。

セルフホストでは事情が変わる。PTY を持っているのはセッションホストなので、**ダッシュボードサーバは何度落としても、走っている Claude Code は死なない**。道連れになるのはセッションホストを落としたときだけ。

### 配布したバイナリでは自己修復が検知だけになる
自己修復は、ダッシュボード自身のソースと Docker を使ってパーサを直す。ワンライナーで入れた PC にはどちらも無いので、そこでは**直せない**。

止まるのは直す工程だけで、**検知は動き続ける**。フォーマットが変わると「パーサの更新が必要です」と画面に出るので、新しい版を入れ直す。黙って構造化ビューが死ぬよりはよい、という割り切り。

### 差し替えたパーサが暴れ出したら、自動で同梱の版へ戻る
自己修復が差し替えたパーサは、**そのあともずっと見張られている**。資源の食い方（メモリの増え方と `read` の回数）が1分続けて桁違いになったとき、短い間に何度も落ちたとき、本体と違う版を名乗ったときは、**1つ前の版（無ければ同梱の版）へ戻し**、理由と実測値を画面とログに出す。

戻す先があるのは**自己修復が差し替えた版だけ**。差し替えを重ねている場合は**1つ前の差し替え版**へ戻り、それが無いときに同梱の版まで下りる。同梱の版そのものが暴れた場合は、戻す先が無いので**パーサを畳んで縮退にする**（ターミナルと指示送信はそのまま使える）。

2026-08-19 に、差し替えられたパーサが 8GB まで育って機械を落としかけたことがある。**そのとき画面にもログにも何も出なかった**——この見張りはそこから来ている。

### 初回起動でカナリアが1回だけ走る
自己修復は「知らない版を初めて見たらサンプルを採って確かめる」作りになっている。対応表が空の初回起動では、**いま使っている版すら「知らない版」**なので、`canary_model`（既定 haiku）で claude が1回起動し、アカウントのクォータを1回分使う。想定どおりの動作だが、初めて起動すると唐突に見える。避けたければ `selfheal_enabled = false` にする。

### 自己修復でパーサを差し替えたあとは、ポインタを外す必要がある
差し替えたパーサは `<state_dir>/parsers/<版>-<時刻>/transcript-parser` に置かれ、`<state_dir>/parser-current` という1行のポインタファイルが指す。**修復内容を本体のソースへ取り込んで作り直したら、このポインタを消す**。消さないと古い差し替え版を使い続ける。

```
cat  ~/.local/state/agentdashboard/parser-current   # いま何を使っているか
rm   ~/.local/state/agentdashboard/parser-current   # 同梱のパーサへ戻す
```

修復の成果は `.selfheal/worktrees/dashboard-maintenance` のブランチにコミットされている。**本体へ取り込むかどうかは人が決める**（自動でプッシュはしない）。

なお**版を切り替えると、このポインタは自動で外れる**。差し替えたパーサは古いソースから作られているので、新しい本体と噛み合う保証が無いため。失うのは修復の成果だけで、必要ならまた検知されて作り直される。

### 版を切り替えられない構成がある
次の2つでは、版の切替そのものを画面に出さない。できないことをボタンにしないため。

| 構成 | なぜ |
|---|---|
| docker compose で立てたサーバ | 箱の中で入れ替えても、次に起こし直すと消える。版は献立表（`compose.yml`）の `image:` で決める |
| Windows | 走っている実行ファイルを置き換えられない作りなので、**3本を書き換えない今回の骨格とは別の作り**が要る。使う人が現れたときに足す |

### 画面から切り替えられないモードがある
モードの切替は TUI の Shift+Tab を送って行う。CLI 側の巡回に入らないモードへは**行けない**。

| モード | 切替 |
|---|---|
| 手動確認 / 編集を自動承認 / プラン | いつでも行ける |
| 自動 | アカウントとモデルが条件を満たすときだけ（満たさない場合、起動時に指定しても**静かに手動確認になる**） |
| 全承認をスキップ | **起動時に選んだセッションでだけ**行ける |
| 確認しない | **決して行けない**。起動時にしか選べない |

選択肢には印を出してあり、押して着かなかった場合も理由が画面に出る。

なお、ターミナル側で Shift+Tab を押して切り替えた場合も表示は追従するが、**1秒ほど遅れる**（端末の表示を見て気づく作りのため）。

### 一覧に載るのはダッシュボードが起動したセッションだけ
ターミナルで手動起動したセッションは検知しない。入力経路を握れないため。

### 利用者のグローバル設定のフックも一緒に動く
セッションへのフック注入は `--settings` を使っており、これは「置き換え」ではなく**追加読み込み**になる。`~/.claude/settings.json` のフック（セッション開始時にスキルを自動起動する設定など）もそのまま発火する。利用者の設定ファイルには一切触らないが、「ダッシュボードが注入したものだけが動く」わけではない。

### その他
- 画面は**ダーク固定**。画面の大半をもともと暗い前提の要素（ターミナルとコードの差分）が占めるため
- `.selfheal/`（修復用の worktree とビルド成果物）は **2GB 規模**になる（実測 1.8GB）。`make clean` で消える
- **入口の鍵は3通り**（`server/crates/server-core/src/auth.rs`）。ローカルで `127.0.0.1` のまま使うなら素通し、LAN へ広げたら合言葉、セルフホストならアカウント。**素通しになるのは、外から誰も来られない構成のときだけ**
- **ブラウザから見て「安全なオリジン」でないと、使えないブラウザの機能がある。** 素の HTTP で別ホストを開いた場合（＝スマホから LAN の IP を叩く形）がこれにあたり、クリップボードへ書く口がそもそも存在しない。**押せば入る**ようにはしてあるが、それも駄目な環境では**値を選べる形で画面に出す**

## 開発

### cargo は必ず `scripts/cargo` 経由で呼ぶ
ホストに Rust ツールチェーンは入っていない。cargo / rustc / clippy / rustfmt / nextest はすべて Docker イメージの中にあり、`scripts/cargo` がその唯一の入口になっている。`cargo: command not found` が出たら、ラッパーを経由し忘れている。

一方 Node はホストのものを使い、ビルドした単一バイナリも**ホストで実行する**（PTY で本物の claude を起動し、ホストの `~/.claude` と利用者のプロジェクトを触るのが本質のため）。

### コマンド
```
make setup        初回セットアップ（Docker イメージ・npm・Playwright の chromium）
make dev          開発時の進め方を表示する（core と Vite を別々の端末で動かす）
make test         Rust と Web のテスト（課金なし。擬似 claude を相手にする）
make test-cli     実CLI統合テスト（★本物の claude が起動し、クォータを消費する）
make e2e          ブラウザからの通し確認（Playwright / 擬似 claude 相手・課金なし）
make perf         性能の実測値を採る（合否ではなく記録用）
make lint         rustfmt / clippy / tsc / oxlint
make build        web ビルド → 単一バイナリ
make ci           lint → test → build を通しで
make fixtures     ゴールデンフィクスチャの採取と匿名化
make clean        ビルド成果物と自己修復の作業場所を消す

  docker が要るもの（CI の既定には入れていない）
make test-compose  永続化層を PostgreSQL に対しても流す
make e2e-compose   サーバ2台＋PostgreSQL＋Valkey をブラウザで通す（前段の Caddy・nginx も）
make dist-local    手元の OS 向けの配布アーカイブを1つ作る
```

`make test` は本物の claude を起動しない。**擬似 claude**（`server/crates/testkit`）を相手にすることで、フックの注入から状態機械・WebSocket・画面までを課金なしで毎回通せるようにしてある。本物を相手にするのは `make test-cli` だけで、こちらは `#[ignore]` 付きなので明示的に叩いたときにしか走らない。

### 構成
```
server/                Cargo workspace
  crates/session-host-core/       PC 側の一式。PTY・フック受信・状態導出・パース・自己修復
  crates/server-core/      ブラウザ配信。WebSocket・REST・DB・アカウント・連絡係
  crates/core/             両者を1プロセスで束ねる配線（ローカルモード）と CLI
  crates/session-host/     セッションホストの中身
  crates/transcript-parser/  JSONL → 表示用ツリー。**自己修復が唯一書き換えてよい範囲**
  crates/protocol/         サーバ・フロント・パーサが共有する型
  crates/dist/             配る一式。実行ファイル3本の入口だけを持つ
  crates/testkit/          フック受信モックと擬似 claude
web/                   React 19 + TypeScript + Vite + Tailwind v4
docs/                  セットアップの手順書と、前段（Caddy・nginx）の設定
docker/                隔離ビルド用イメージと compose 一式
fixtures/              ゴールデンフィクスチャ（自己修復のテストゲートを兼ねる）
scripts/               cargo・dist のラッパー、フィクスチャ採取・匿名化
```

**PTY を持つのは `session-host-core` だけ、DB と連絡係を持つのは `server-core` だけ。** この線はコンパイラが守っており、破れていないことを `crates/core/tests/dependencies.rs` が機械で見ている。

**画面（ブラウザ）に口を足したら `server/crates/core/tests/cli_surface.toml` へ足す。** 画面でできる操作は CLI（`agentdashboard session …` など）でも同じようにできる、という約束の台帳で、CLI へ写したか・載せない判断をしたかが1口ずつ残る。実コードと食い違うと `make ci` が落ちる。

パーサを別プロセスに切り出しているのは自己修復のためだ。「フォーマットが変わったらパーサを直して差し替える」が成立するには、**直す対象**と**動き続けなければならないもの**（PTY 上の生きたセッション）がプロセスとして分かれている必要がある。

### フィクスチャを触るとき
**本リポジトリは公開されている。** `fixtures/` に入れる実トランスクリプトはそのまま世界に見える。Claude Code のトランスクリプトには、採取内容と無関係に**その環境の構成情報**（導入済みスキルの一覧・接続中の MCP サーバ・フックのコマンド行など）を書き出すレコードが混ざるため、採取物は必ず `scripts/sanitize-fixtures.py` を通すこと（`make fixtures` は通す）。詳細は `fixtures/README.md`。
