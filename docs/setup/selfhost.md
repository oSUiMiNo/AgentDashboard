# セルフホストで使う

サーバを1台立てて、そこへ**複数の PC** を繋ぐ使い方。外出先のスマホから、家の PC で動いているセッションを見て操作できる。

1台で完結させたいだけなら [ローカルで使う](local.md) のほうが早い（サーバは要らない）。

```
             ブラウザ（スマホ・別の PC）
                    │
              ダッシュボードサーバ ── 記録の置き場所
                    │              └ 連絡係（2台以上に増やすときだけ）
         ┌──────────┴──────────┐
    仕事用ノート            自宅デスクトップ   ← agentdashboard-agent
```

**セッションの実体は PC の中**にある。サーバを再起動しても、走っている Claude Code は死なない。

## どちらの道で立てるか
立て方は2つある。**あとから乗り換えられる**ので、まずは道①で始めて構わない。

| | 道①　実行ファイルだけ | 道②　docker compose |
|---|---|---|
| 要るもの | **なし** | Docker |
| 手数 | 2コマンド・〜2分 | 2コマンド・〜2分 |
| 記録の置き場所 | ファイル1個（SQLite）が自動でできる | PostgreSQL |
| 落ちたとき | 自分で起き上がらせる設定を入れる | 勝手に起き上がる |
| サーバを2台以上に増やす | できない | できる |

迷ったら道①。**PC を何台繋いでも道①のままでよい**——増やす必要があるのは「ダッシュボードのサーバ」を複数台にしたいときだけで、それは同時に使う人が増えてからの話になる。

## 道①　実行ファイルだけで立てる
Docker も PostgreSQL も要らない。[ローカルで使う](local.md) と同じ実行ファイルを、サーバの役で起動する。

### 1. 入れる（〜30秒）
```
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/oSUiMiNo/AgentDashboard/releases/latest/download/agentdashboard-installer.sh | sh
```

### 2. 起動する（〜10秒）
```
AGENTDASHBOARD_BIND_ADDR=0.0.0.0 agentdashboard --mode server
```

`--mode server` は「PC 側を持たない」という意味。この機械では claude を起動せず、繋いでくる PC の面倒だけを見る。**だからサーバに `claude` は要らない。**

待ち受けを広げる（`0.0.0.0`）のは、外から届かせるため。**鍵はこのあと作るアカウントのログイン**なので、広げること自体は危険ではない。

記録の置き場所は**指定しなければ自動でできる**。1ファイル（SQLite）が作られ、表の形も起動時に当たる。バックアップはそのファイルを控えるだけでよい。

**場所は OS で違う**ので、決め打ちで覚えずに実行ファイルへ聞く。

```
agentdashboard state-dir
```

設定（`state_dir`）や環境変数で変えていても、返るのは**実際に使っている場所**。

### 3. 管理者を作る（〜1分）
ブラウザで **`http://<サーバ>:8787/setup`** を開き、名前とパスワードを決める。

この画面は**一度きり**しか開かない。作ったあとは通常のログイン画面になる。

### 4. PC を繋ぐ（〜1分半）
[ペアリング](pairing.md) へ。トークンを発行して、PC 側でエージェントを起動する。

ダッシュボードに PC が現れたら完了。

### 落ちても起き上がるようにする
道①は、そのままだと再起動で止まったままになる。Linux なら常駐の設定を1つ置けばよい。雛形は `docs/service/agentdashboard.service` にある。

```
sudo cp docs/service/agentdashboard.service /etc/systemd/system/
sudo systemctl enable --now agentdashboard
```

利用者名と置き場所は環境に合わせて書き換える。ファイルの中にどこを直すか書いてある。

### 版を上げる・戻す
道①なら**画面から切り替えられる**。設定画面（`/settings`）の「ダッシュボードの版」で、新しい版を取ってきたり、前の版へ戻したりできる。

選ぶだけでは何も起きない——**効くのは次に起こしたとき**で、いま動いているセッションは巻き添えにならない。すぐ反映したいときは「いま入れ替える」を押す。押す前に、何枚が抜け殻になるかが出る。

常駐の設定を置いてあれば、落としたあとは自動で起き上がる。置いていない場合は端末で `agentdashboard` を実行し直す。

## 道②　docker compose で立てる
記録を PostgreSQL に置き、勝手に起き上がる形。**サーバを2台以上に増やせるのはこちら。**

### 1. 献立表を取ってきて起こす（〜2分）
```
curl -O https://raw.githubusercontent.com/oSUiMiNo/AgentDashboard/main/docker/compose.yml
docker compose up -d
```

3つ立つ。

| サービス | 役 |
|---|---|
| `dashboard` | 本体。`8787` で待ち受ける |
| `postgres` | 記録の置き場所（一覧・履歴・アカウント） |
| `valkey` | サーバを2台以上並べるときの連絡係。1台なら**無くてよい** |

**データベースの作り込みは要らない。** 表は起動時に自動で当たる。

**ソースコードは要らない。** 本体は出来合いのものを取ってくる（`ghcr.io/osuimino/agentdashboard`）。

### 2. 管理者を作る（〜1分）
道①の手順3と同じ。**`http://<サーバ>:8787/setup`** を開く。

### 3. PC を繋ぐ（〜1分半）
道①の手順4と同じ。[ペアリング](pairing.md) へ。

### 版を上げる
献立表には**版が固定して書いてある**。取り直しただけで勝手に上がらないようにするためで、上げるかどうかは利用者が決める。

```
# compose.yml の image: の版を書き換えてから
docker compose pull
docker compose up -d
```

**上げると記録の表の形も一緒に変わる。** 形だけは巻き戻さないので、**版を下げても記録は元に戻らない**（古い版が知らない形が当たっていると、そもそも起動できない）。先に `postgres` のデータを控えておくとよい。

なお道①にある**画面からの版の切替は、この道では出ない**。箱の中で入れ替えても次に起こし直すと消えるので、できないことをボタンにしていない。こちらでの版上げは上の3行が正となる。

## インターネットから使う
アプリは HTTP しか話さない。TLS は前段のリバースプロキシで終端する。設定例と注意点は [リバースプロキシ](reverse-proxy.md) にある。

ドメインを持っていないなら、Tailscale や Cloudflare Tunnel で繋ぐ手もある。どちらの場合も、アプリ側でやることは同じ1つ：

```
AGENTDASHBOARD_COOKIE_SECURE=true
```

HTTPS で開くのにこれを付けないと、**入館証が平文でも送られる**。

## サーバを2台以上に増やす
道②の `dashboard` を複数立てて、前段で振り分ける。揃えるのは2つだけ。

| 環境変数 | 揃える理由 |
|---|---|
| `DATABASE_URL` | 一覧も履歴もここが正。台ごとに違うと別々のダッシュボードになる |
| `VALKEY_URL` | 揮発の知らせ（画面・指示・在席）を配る。**1台なら要らない** |

それ以外は台ごとに違ってよい。

ブラウザが繋いだ台に、その PC が繋がっていなくても操作できる。片方の台を落としても、**セッションは死なない**（実体は PC の中にある）。

**道①からは直接は増やせない。** 記録がファイル1個（SQLite）で、別の機械から同時に読み書きできないため。増やすときは PostgreSQL へ移すことになる。

## 設定
環境変数はすべて `AGENTDASHBOARD_<大文字のキー>`。キーの一覧は `server/config.toml.example` が兼ねている。道①なら `config.toml` に書いてもよい（`--config` で渡す）。

慣行として `DATABASE_URL` と `VALKEY_URL` は接頭辞なしでも受ける（接頭辞つきが勝つ）。

## うまくいかないとき
| 症状 | 見るところ |
|---|---|
| `agentdashboard: command not found`（道①） | `~/.local/bin` が PATH に入っているか。入れ直すか、シェルを開き直す |
| 外から開けない（道①） | `AGENTDASHBOARD_BIND_ADDR=0.0.0.0` を付けたか。既定は同じ機械からしか開けない |
| `/setup` が「もう作れません」と言う | 管理者は作成済み。ログイン画面（`/`）から入る |
| ログインしてもすぐ弾かれる | HTTPS で開いていないのに `AGENTDASHBOARD_COOKIE_SECURE=true` にしていないか。Secure の入館証は HTTPS でしか送られない |
| PC が一覧に出ない | [ペアリング](pairing.md) の「うまくいかないとき」へ |
| 一部のブラウザにだけ更新が来ない | 台を増やしたのに `VALKEY_URL` を渡していないか。画面上部に連絡係の縮退が出る |
