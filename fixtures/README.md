# ゴールデンフィクスチャ

---
<br/>
<br/>

## これは何か
Claude Code が実際に書き出したトランスクリプト（JSONL）の実物を、バージョン別に保存したもの。transcript-parser のテストデータであり、同時に**自己修復機構のテストゲート**を兼ねる。

新しいバージョンへ対応するためにパーサを書き換えたとき、ここにある過去バージョンのフィクスチャが全て変換できることが、自動反映の唯一の合格条件になる（設計§9 の安全条件2）。つまりこのディレクトリは「新対応が旧フォーマットを壊していないこと」を担保する装置である。

## ディレクトリ構成
```
fixtures/
└ v<Claude Code のバージョン>/
   ├ basic-tools/
   │   └ session.jsonl              ツールコール・Edit差分・Bash・Write を含む本体
   └ subagent/
       ├ session.jsonl              サブエージェントを起動した親セッション
       └ session/
           └ subagents/
               ├ agent-<id>.jsonl      サブエージェント側のトランスクリプト
               └ agent-<id>.meta.json  親のツールコールIDとエージェント種別
```

`agent-*.meta.json` は `agentType` / `toolUseId` / `spawnDepth` を持つ。パーサはこの `toolUseId` を頼りに、親セッションの該当ツールコールへ子ツリーをマウントする（設計§8）。

### `synthetic/` は例外で、手で書いたもの
`synthetic/` 配下だけは**実採取ではなく手書き**である。`rewound/` は `/rewind` で会話が分岐した状態（同じファイルに `parentUuid: null` の根が2つある）を最小の形で表す。

手書きにしているのは、この状態の実採取物が対話モードでしか作れず、採取すると環境情報が混入するため（公開リポジトリに置けない）。バージョン別ディレクトリに置いていないのは、特定バージョンの実物ではないことを取り違えないようにするため。**自己修復のテストゲート（過去バージョンの互換確認）には数えない。**

## 採取のしかた
```
make fixtures
```

実体は `scripts/gen-fixtures.sh`。**ホストで実行する**（本物の claude CLI と認証情報がホストにあるため）。

やっていることは次のとおり。

1. 使い捨ての一時ディレクトリを作り、当たり障りのない合成ファイル（メモとサンプルコード）を置く
2. Claude 関連の環境変数を落とした状態で `claude --session-id <採番したUUID> -p ...` を実行する
3. `~/.claude/projects/` 配下から採番したIDのトランスクリプトを探して `fixtures/v<バージョン>/` へ写す
4. 4要素（ツールコール／Edit差分／サブエージェント／sidechain）が揃っているかを機械的に確認する
5. `scripts/sanitize-fixtures.py` で機微情報を置換し、残っていないことを検査する

## 実運用ログではなく「その場で作る」理由
`~/.claude/projects/` には業務プロジェクトを含む実ログが大量にあるが、それらは使わない。匿名化を頑張るより、**最初から機微情報が入らない作り方をする**ほうが漏れの余地が構造的に無いという判断。

それでも実行環境そのものに由来する情報は必ず混入するため、採取のたびに `sanitize-fixtures.py` を通す。落としているのは2種類。

1. **文字列レベル**：ホームディレクトリの絶対パス・ユーザ名・ホスト名、および採取物から動的に見つけた Skill ツールコールのスキル名を置換する
2. **レコードレベル**：`type: "attachment"` のレコードは中身を落として形だけ残す

スキル名を置換対象にしているのは、利用者が自分で定義したスキルの名前が環境固有の情報にあたるため。フックがセッション開始時にスキルを起動する設定になっていると、採取のたびに必ず本文へ混入する。スクリプトに具体的な名前を書くとそれ自体が公開情報になるので、ハードコードせず採取物から抽出している。

2 が必要なのは、`attachment` が採取内容と無関係に**その環境の構成情報**（導入済みスキルの全一覧と説明・カスタムサブエージェント・接続中のMCPサーバ・フックのコマンド行）を書き出すため。何が入るか事前に列挙できないので文字列置換では消せない。パーサ側では attachment は表示対象外として読み飛ばす種別なので、形だけ残せばフィクスチャとしての価値（表示対象外レコードが混ざったJSONLを正しく処理できるかの検証）は保てる。

置換後は残存検査を行い、1件でも残っていれば異常終了するので、目視確認に頼らずに済む。**本リポジトリは公開されている**ため、この工程を飛ばしてはいけない。

## 注意
- フィクスチャは**バージョンごとに残す**。古いバージョンのディレクトリを消すと、後方互換の検証ができなくなる
- 採取したファイルはコミットする。テストデータとして参照され続けるため
