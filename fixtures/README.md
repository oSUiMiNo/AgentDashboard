# ゴールデンフィクスチャ

---
<br/>
<br/>

## これは何か
Claude Code が実際に書き出したトランスクリプト（JSONL）の実物を、バージョン別に保存したもの。transcript-parser のテストデータであり、同時に**自己修復機構のテストゲート**を兼ねる。

新しいバージョンへ対応するためにパーサを書き換えたとき、ここにある過去バージョンのフィクスチャが全て変換できることが、自動反映の唯一の合格条件になる（設計§9 の安全条件2）。つまりこのディレクトリは「新対応が旧フォーマットを壊していないこと」を担保する装置である。

## ディレクトリ構成
```
fixtures/
├ v<Claude Code のバージョン>/
│  ├ basic-tools/
│  │   └ session.jsonl              ツールコール・Edit差分・Bash・Write を含む本体
│  ├ failing-tools/
│  │   └ session.jsonl              ツール自身が失敗した形（結果ブロックの is_error）と
│  │                                1ターンで複数ファイルを編集した並び
│  ├ subagent/
│  │   ├ session.jsonl              サブエージェントを起動した親セッション
│  │   └ session/
│  │       └ subagents/
│  │           ├ agent-<id>.jsonl      サブエージェント側のトランスクリプト
│  │           └ agent-<id>.meta.json  親のツールコールIDとセッションホスト種別
│  ├ nested-subagent/               深さ2以上（meta の鍵が parentAgentId に変わる）
│  └ terminal/                      端末録画（下記。トランスクリプトではなく画面の実物）
│      ├ basic.cast
│      ├ interactive.cast
│      └ resize.cast
└ synthetic/                        手書き（下記）
   ├ rewound/
   └ interactive-only/
```

`agent-*.meta.json` は `agentType` / `toolUseId` / `spawnDepth` を持つ。パーサはこの `toolUseId` を頼りに、親セッションの該当ツールコールへ子ツリーをマウントする（設計§8）。

「ツールが失敗した」形が2種類あることに注意する。**利用者に拒否された**場合は `toolUseResult` が文字列になり（`basic-tools` の Skill）、**ツール自身が失敗した**場合は結果ブロックの `is_error` が立つ（`failing-tools` の Read）。オブジェクト前提で書くと前者で落ち、`is_error` を見ないと後者が成功として表示される。

### `synthetic/` は例外で、手で書いたもの
`synthetic/` 配下だけは**実採取ではなく手書き**である。

| ラベル | 何を表すか |
|---|---|
| `rewound/` | `/rewind` で会話が分岐した状態（同じファイルに `parentUuid: null` の根が2つある）を最小の形で |
| `interactive-only/` | **対話モードでしか現れないレコード種別**（`file-history-snapshot` / `file-history-delta` / `mode` / `permission-mode` / `summary`）が本文の間に挟まった状態 |

手書きにしているのは、どちらも実採取物が対話モードでしか作れず、採取すると環境情報が混入するため（公開リポジトリに置けない）。バージョン別ディレクトリに置いていないのは、特定バージョンの実物ではないことを取り違えないようにするため。**「過去バージョンを壊していないこと」の担保には数えない**（実物ではないので、バージョン間の互換の証拠にならない）。

ただし**ゲートの巡回対象ではある**。`fixtures/*/*/session.jsonl` を発見して回る作りなので、これらも「不明なイベントを出さずに読めること」を毎回確かめられる。`interactive-only/` を置いている理由がまさにそこにあって、これらの種別は**ヘッドレス採取のフィクスチャには1件も入らない**ため、分類から漏れてもゲートは何も言わない。実際にフェーズ3で `file-history-delta` が漏れており、ファイルを1つ編集するたびに「不明なイベント」が履歴へ混ざっていた。

`interactive-only/` のレコードのうち、キー構成は実物から採った（値は入れ替えてある）。`summary` だけは手元の実データに現れなかったため最小の形にしてあるが、分類は `type` だけで決まるのでゲートの役目は果たす。

### `terminal/` は端末の録画で、用途が別
ここまでのフィクスチャは Claude Code が**書き出した JSONL**だが、`terminal/` に入っているのは
**端末に流れたバイト列そのもの**である。セルフホスト化でリモートのブラウザへ画面を配信する
（セルフホスト化設計§7）ために、セッションホスト内の端末エミュレータへ食わせる実物が要る。

| ラベル | 何が録れているか | 何に使うか |
|---|---|---|
| `basic.cast` | 起動・日本語の会話3ターン・スピナー・色付きのツール表示 | 色／全角／スピナーの再現、画面と差分の大きさ、スクロールバック |
| `interactive.cast` | 権限プロンプトへの応答・`/rewind` のメニュー操作 | 入力から再描画までの遅れ（ホットウィンドウの妥当性） |
| `resize.cast` | 出力の途中で 120x40 → 80x24 → 140x50 とリサイズ | 大きさが変わったときの描き直し |

形式は **asciicast v2**（1行目がヘッダの JSON、以降が `[経過秒, "o"|"i"|"r", データ]`）。
出力だけでなく**入力とリサイズにも時刻が付く**のが要点で、これが無いと「入力してから画面が
返るまで」を測れない。

採取は `make record-terminal`（実体は `scripts/record-terminal.sh`）。録画そのものは
`server/crates/session-host-core/tests/pty_record.rs` にあり、**製品と同じ PTY 経路**（同じ TERM・
同じ環境変数の許可リスト・同じ読み取り粒度）で録る。ここがずれると、本番でエミュレータへ
届くバイト列とは別物を録ることになる。

読む側は `make probe-screen`（`tests/screen_probe.rs`）。

**匿名化で桁がずれている箇所がある。** 起動直後の枠には利用者のアカウント名とメールが
出るので置き換えているが、置き換えた文字列は元と長さが違う。枠の桁揃えはその分だけ
実際の画面と異なる。エミュレータの検証（往復の再現性・差分の追随）には影響しない。

## 採取のしかた
```
make fixtures        # トランスクリプト（JSONL）
make record-terminal # 端末録画（.cast）
```

実体は `scripts/gen-fixtures.sh`。**ホストで実行する**（本物の claude CLI と認証情報がホストにあるため）。

やっていることは次のとおり。

1. 使い捨ての一時ディレクトリを作り、当たり障りのない合成ファイル（メモとサンプルコード）を置く
2. Claude 関連の環境変数を落とした状態で `claude --session-id <採番したUUID> -p ...` を実行する
3. `~/.claude/projects/` 配下から採番したIDのトランスクリプトを探して `fixtures/v<バージョン>/` へ写す
4. 4要素（ツールコール／Edit差分／サブエージェント／sidechain）が揃っているかを機械的に確認する
5. `scripts/sanitize-fixtures.py` で機微情報を置換し、残っていないことを検査する

## 実運用ログではなく「その場で作る」理由
`~/.claude/projects/` には業務プロジェクトを含む実ログが大量にあるが、それらは使わない。匿名化を頑張るより、**最初から機微情報が入らない作り方をする**ほうが漏れの余地が構造的に無いという判断。

それでも実行環境そのものに由来する情報は必ず混入するため、採取のたびに `sanitize-fixtures.py` を通す。落としているのは3種類。

1. **文字列レベル**：ホームディレクトリの絶対パス・ユーザ名・ホスト名、および採取物から動的に見つけた Skill ツールコールのスキル名を置換する
2. **レコードレベル**：`type: "attachment"` のレコードは中身を落として形だけ残す
3. **アカウント由来**：ログイン中の表示名・メール・所属・UUID を置換し、形がメールアドレスの文字列はまとめて差し替える

スキル名を置換対象にしているのは、利用者が自分で定義したスキルの名前が環境固有の情報にあたるため。フックがセッション開始時にスキルを起動する設定になっていると、採取のたびに必ず本文へ混入する。スクリプトに具体的な名前を書くとそれ自体が公開情報になるので、ハードコードせず採取物から抽出している。

2 が必要なのは、`attachment` が採取内容と無関係に**その環境の構成情報**（導入済みスキルの全一覧と説明・カスタムサブエージェント・接続中のMCPサーバ・フックのコマンド行）を書き出すため。何が入るか事前に列挙できないので文字列置換では消せない。パーサ側では attachment は表示対象外として読み飛ばす種別なので、形だけ残せばフィクスチャとしての価値（表示対象外レコードが混ざったJSONLを正しく処理できるかの検証）は保てる。

3 が要るのは、**claude の TUI が起動直後の枠にログイン中のアカウントを出す**ため（実測。端末録画の初回採取で検出した）。表示名は OS のユーザ名とは別物なので 1 の規則では捕まらない。規則をスクリプトに書き並べる方式は採らない——書けばそれ自体が公開情報になる。採取した環境の `~/.claude.json` から読み取ってその場で規則にしている。

端末録画には**もう一段の検査**がある。中身が生の端末バイト列なので、行単位の置換だけでは足りない。

- 同じ文字列がチャンクの境目で2つのイベントに割れていると、どちらにも完全な形では現れず、置換も通常の検査もすり抜ける → **イベントをつなぎ直してから**検査する
- TUI は文字列の途中でカーソルを動かす → **エスケープシーケンスを落とした版**でも検査する
- 逆に、置換をファイルの文字列へ直接当ててはいけない。`ESC[30G` の直後にアドレスが続くと、正規表現が `30G...` から一致してカーソル移動の指定ごと消してしまう（実測で踏んだ）。録画だけはイベントをデコードしてから、エスケープシーケンスの外側だけを直す

置換後は残存検査を行い、1件でも残っていれば異常終了するので、目視確認に頼らずに済む。**本リポジトリは公開されている**ため、この工程を飛ばしてはいけない。

## 注意
- フィクスチャは**バージョンごとに残す**。古いバージョンのディレクトリを消すと、後方互換の検証ができなくなる
- 採取したファイルはコミットする。テストデータとして参照され続けるため
